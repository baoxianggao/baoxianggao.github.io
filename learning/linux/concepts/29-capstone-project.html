29 · 综合实战项目 ​

前置：28 高可用与集群 · 预计：3~4 小时

概念简介 ​

前面 28 篇教了零件，本篇把它们装成一台真正的生产服务器。目标：从一台全新 Ubuntu 22.04 开始，完成「环境初始化 → 部署 Nginx + 后端应用 → HTTPS 与防火墙 → 监控告警 → 备份与日志轮转 → 故障演练」全链路，达到可以直接对外提供服务、出故障能定位能恢复的水平。

项目分 7 个阶段，每阶段有明确验收标准——验收标准不是"配完了"，而是"能证明它工作"。这也是 L5 考核的项目载体：全部完成后用 /assess linux L5 让 AI 按知识/代码/项目/架构/评审五类题考核。建议用虚拟机（VirtualBox/KVM 装 Ubuntu 22.04 Server，2 核 2GB 起步）实操，每完成一阶段按验收标准自检。

核心内容 ​

阶段 1 · 环境初始化：用户、安全、基础包 ​

bash
# 1. 系统更新到最新(安全基线的第一步)
sudo apt update && sudo apt upgrade -y

# 2. 创建部署用户:不用 root 跑服务,最小权限原则
sudo adduser deploy
sudo usermod -aG sudo deploy          # 仅管理操作需要 sudo

# 3. 拷贝本机 SSH 公钥(密钥认证,禁密码登录在阶段 4)
ssh-copy-id deploy@服务器IP

# 4. 基础工具链
sudo apt install -y curl wget git vim tree htop \
    net-tools tcpdump mtr nginx python3-pip

验收标准：ssh deploy@IP 免密登录成功；sudo whoami 输出 root；apt list --upgradable 为空。

阶段 2 · 部署后端应用（以 Node.js 为例） ​

bash
# 1. 安装 Node.js 20 LTS(用官方源,apt 自带版本太旧)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 2. 准备应用目录与代码(生产上这里是你的 git 代码)
sudo mkdir -p /opt/myapp && cd /opt/myapp
cat > app.js <<'EOF'
// 最小生产示例:带健康检查端点 /healthz 的 HTTP 服务
const http = require('http');
const PORT = 3000;
const server = http.createServer((req, res) => {
  if (req.url === '/healthz') { res.writeHead(200); res.end('ok'); return; }
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ service: 'myapp', time: new Date().toISOString() }));
});
server.listen(PORT, () => console.log(`listening on ${PORT}`));
EOF
sudo chown -R deploy:deploy /opt/myapp   # 非 root 运行,目录归 deploy 所有
ini
# 3. systemd 服务托管:开机自启 + 崩溃自动拉起 + 资源兜底
# /etc/systemd/system/myapp.service
[Unit]
Description=MyApp 后端服务
After=network.target

[Service]
User=deploy
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/node /opt/myapp/app.js
Restart=on-failure          # 崩溃自动重启(仅非正常退出)
RestartSec=3
Environment=NODE_ENV=production
LimitNOFILE=65535           # 高并发必备(24 篇所学)

[Install]
WantedBy=multi-user.target
bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
systemctl status myapp && curl http://127.0.0.1:3000/healthz

验收标准：systemctl status myapp 显示 active；systemctl is-enabled 输出 enabled（重启服务器后自动启动）；kill -9 进程后 3 秒内自动拉起；journalctl -u myapp 有结构化日志。

阶段 3 · 部署 Nginx：反向代理 ​

nginx
# /etc/nginx/sites-available/myapp.conf
server {
    listen 80;
    server_name _;                # 生产替换为你的域名

    location / {
        proxy_pass http://127.0.0.1:3000;
        # 透传真实客户端 IP(25 篇的坑:不透传后端拿不到用户地址)
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 30s;
    }
}
bash
sudo ln -s /etc/nginx/sites-available/myapp.conf /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default        # 移除默认站点
sudo nginx -t && sudo systemctl reload nginx
curl http://服务器IP/healthz                     # 外网 80 端口可达

验收标准：外网 curl http://IP/healthz 返回 ok；ss -tlnp | grep :80 只有 Nginx 监听 80（应用不直接暴露）；Nginx access log 记录了真实客户端 IP。

阶段 4 · 防火墙与安全加固 ​

bash
# 1. ufw 防火墙:默认拒绝,只放行必要端口(17 篇所学)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80,443/tcp
sudo ufw enable && sudo ufw status verbose

# 2. SSH 加固:禁密码登录、禁 root 登录
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart sshd
# !!! 先开新终端确认能登录,再断旧连接(锁自己的门是最常见的翻车)

# 3. fail2ban 防暴力破解 + 自动安全更新
sudo apt install -y fail2ban unattended-upgrades
sudo systemctl enable --now fail2ban unattended-upgrades

验收标准：防火墙只开放 22/80/443（从外部 curl 3000 端口不通）；密码登录被拒（提示 Permission denied 而非继续要密码）；root 直连被拒；fail2ban-client status sshd 有活跃 jail。

阶段 5 · HTTPS：证书与强制跳转 ​

有域名：sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d 你的域名（自动配证书与跳转）。无域名（学习场景）用自签证书验证全链路：

bash
# 1. 生成自签证书(学习用;生产必须 Let's Encrypt 等正规 CA)
sudo mkdir -p /etc/nginx/certs
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/nginx/certs/myapp.key -out /etc/nginx/certs/myapp.crt \
    -subj "/CN=myapp"
nginx
# 2. 修改站点配置:80 跳转 + 443 服务
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;   # 强制 HTTPS
}
server {
    listen 443 ssl;
    server_name _;
    ssl_certificate /etc/nginx/certs/myapp.crt;
    ssl_certificate_key /etc/nginx/certs/myapp.key;
    ssl_protocols TLSv1.2 TLSv1.3;          # 禁用旧协议
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
bash
sudo nginx -t && sudo systemctl reload nginx
curl -k https://127.0.0.1/healthz          # -k 忽略自签校验(仅测试)

验收标准：curl http://IP/ 返回 301 且 Location 指向 https；curl -k https://IP/healthz 返回 ok；openssl x509 -in /etc/nginx/certs/myapp.crt -noout -dates 显示证书在有效期内。

阶段 6 · 监控告警：Prometheus 最小闭环 ​

bash
# 1. node_exporter:暴露主机指标(CPU/内存/磁盘/网络)
wget -q https://github.com/prometheus/node_exporter/releases/download/v1.8.2/node_exporter-1.8.2.linux-amd64.tar.gz
tar xzf node_exporter-*.tar.gz && sudo mv node_exporter-*/node_exporter /usr/local/bin/
sudo useradd -r -s /usr/sbin/nologin node_exporter
# 2. 注册 systemd 服务
sudo tee /etc/systemd/system/node_exporter.service >/dev/null <<'EOF'
[Unit]
Description=Node Exporter
After=network.target
[Service]
User=node_exporter
ExecStart=/usr/local/bin/node_exporter
Restart=on-failure
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now node_exporter
curl http://127.0.0.1:9100/metrics | head -5     # 指标已输出
yaml
# 3. Prometheus 配置(二进制下载同 node_exporter 流程,或 docker run -d -p 9090:9090 prom/prometheus)
# /etc/prometheus/prometheus.yml
global:
  scrape_interval: 15s
rule_files:
  - alerts.yml
scrape_configs:
  - job_name: node
    static_configs:
      - targets: ['127.0.0.1:9100']
yaml
# /etc/prometheus/alerts.yml:两条核心告警
groups:
  - name: basic
    rules:
      - alert: 磁盘使用率过高
        expr: (1 - node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 > 85
        for: 2m
        annotations: { summary: "根分区使用率超过 85%" }
      - alert: 服务不可用
        expr: up == 0
        for: 1m
        annotations: { summary: "{{ $labels.instance }} 采集失败" }

验收标准：curl http://127.0.0.1:9100/metrics 有数据；promtool check config 校验配置合法、target 为 UP；故意停掉 node_exporter 后 15 秒内 up == 0 告警触发。

阶段 7 · 备份与日志轮转 + 故障演练 ​

bash
# 1. logrotate:日志不轮转 = 磁盘迟早被日志吃满(27 篇的坑)
sudo mkdir -p /var/log/myapp
sudo tee /etc/logrotate.d/myapp >/dev/null <<'EOF'
/var/log/myapp/*.log {
    daily
    rotate 14              # 保留 14 份
    compress               # 压缩轮转出的旧日志
    missingok
    notifempty
    create 0640 deploy deploy
}
EOF
sudo logrotate -d /etc/logrotate.d/myapp   # -d 演练模式,确认配置无误

# 2. 备份脚本:代码+数据,异地+定期(21 篇所学,挂 cron)
sudo tee /usr/local/bin/backup.sh >/dev/null <<'EOF'
#!/usr/bin/env bash
# 备份 /opt/myapp 保留 7 天,并同步到异地备份机
set -euo pipefail
STAMP=$(date +%Y%m%d_%H%M%S)
mkdir -p /var/backups/myapp
tar czf "/var/backups/myapp/myapp_${STAMP}.tar.gz" -C /opt/myapp .
find /var/backups/myapp -name "myapp_*.tar.gz" -mtime +7 -delete
rsync -avz /var/backups/myapp/ backup-host:/data/backups/   # 异地容灾
echo "[$(date '+%F %T')] 备份完成 ${STAMP}" >> /var/log/backup.log
EOF
sudo chmod +x /usr/local/bin/backup.sh
(crontab -l 2>/dev/null; echo "0 3 * * * /usr/local/bin/backup.sh") | crontab -

# 3. 故障演练清单(28 篇所学:高可用是练出来的)
# □ 服务崩溃: systemctl kill -s KILL myapp -> 验证 3 秒自动拉起
# □ 磁盘写满: dd if=/dev/zero of=/tmp/fill bs=1M count=1024 -> 验证告警收到
# □ 进程假死: kill -STOP <node_pid> -> 验证 healthz 超时与人工处置
# □ 日志风暴: 循环写日志 -> 验证 logrotate 生效、磁盘不涨
# 每项演练后:清理现场、记录耗时与问题、写演练报告

验收标准：/var/backups/myapp/ 有当天备份且 tar -tzf 能列出内容；ls /var/log/myapp/ 能看到轮转压缩产物；演练清单每项能复现并能恢复。

L5 考核说明 ​

本项目是 Linux L5（专家/架构师）考核的项目载体。完成全部 7 个阶段并逐项验收后运行 /assess linux L5。考核覆盖：知识题（本篇各概念的原理与取舍）、代码题（systemd 单元文件/脚本正确性）、项目题（本项目架构讲解、故障怎么定位）、架构题（流量翻 10 倍怎么演进）、评审题（给一段有问题的配置找隐患）。建议把各阶段验收证据（systemctl 状态、curl 结果、告警触发）整理成《项目验收报告》，考核时直接引用。

常见陷阱 ​

  • SSH 加固顺序反了：先禁密码登录再测试新连接，把自己锁在门外。先开新终端验证，再重启 sshd。
  • 防火墙先改 deny：没放行 SSH 就把默认策略改成 deny，直接失联。顺序：放行 ssh → deny → enable。
  • 应用以 root 跑：systemd 漏写 User=deploy，应用带 root 权限，安全基线归零。
  • 3000 端口裸奔：应用直接对公网监听，Nginx 这层的日志/限流/探活全丢了。
  • 日志不轮转、备份不验证：几天后磁盘被日志吃满；备份了但从未恢复验证过，等于没有备份。
  • 自签证书上生产、监控端口对公网：自签只用于学习；9100/9090 必须被防火墙挡住。

练习建议 ​

  1. 基础：完成阶段 1-3（初始化 + 部署 + 反代），输出三张验收证据（ssh 登录、systemctl 状态、curl 结果）。
  2. 进阶：完成阶段 4-5（加固 + HTTPS），用 ufw status、ss、openssl 各给出安全证据；用 fail2ban-client status 确认 jail 活跃。
  3. 综合：完成阶段 6-7 全部内容 + 故障演练清单，整理《项目验收报告》，运行 /assess linux L5 完成考核。

用 /practice linux 综合实战项目 生成更多针对性练习。
