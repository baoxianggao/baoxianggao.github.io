题目 1 · 跑通第一个程序并拆出视图（对应概念 01） ​

难度：基础

题目：用 Xcode 创建一个 SwiftUI 项目（Interface 选 SwiftUI），把屏幕文字改成「Hello, 张三」，并抽成一个独立的 Greeting(name: String) 视图，在 ContentView 里使用两次（传入不同名字）。再加一个按钮，点击后在控制台输出一行日志。

要求：

  • App 入口保留 @main + App 协议 + WindowGroup
  • Greeting 是遵循 View 协议的 struct，name 是它的属性
  • 两个 Greeting 用 VStack 纵向排列
  • 能说清 MyAppApp.swift 与 ContentView.swift 各自的职责

提示：前端锚点——@main 标记的 App 结构 ≈ main.jsx，WindowGroup { ContentView() } ≈ 挂载根组件，View 协议的 body ≈ 函数组件的返回值。

参考答案
swift
// MyAppApp.swift（App 入口，@main 标记，别去找 main() 函数）
import SwiftUI

@main
struct MyAppApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()   // 根视图，类比 App.jsx
        }
    }
}

// ContentView.swift
import SwiftUI

struct ContentView: View {
    var body: some View {
        VStack(spacing: 12) {          // 纵向排列，spacing 类比 gap
            Greeting(name: "张三")
            Greeting(name: "李四")
            Button("打个招呼") {
                print("按钮被点击了")     // 输出到 Xcode 控制台
            }
        }
    }
}

// 自定义视图：遵循 View 协议，属性 name 就是 props
struct Greeting: View {
    let name: String

    var body: some View {
        Text("Hello, \(name)")        // 字符串插值用 \() 而非 ${}
    }
}

要点解析：

  1. MyAppApp.swift 的职责是「作为程序入口，声明窗口场景并挂载根视图」；ContentView.swift 是「根视图，页面内容的起点」。
  2. @main 是 Swift 5.3+ 的入口标记（SwiftUI 项目里没有 main() 函数可找）。
  3. some View 是不透明返回类型：body 必须返回单一具体类型，条件返回不同类型时用 if-else 或 @ViewBuilder 包裹。

常见错误：

  1. 把两个 Greeting 直接并列写在 body 里不套容器 → 编译报错（body 只能返回一个视图）。
  2. 插值写成 "Hello, ${name}" → Swift 一律用 \(name)，${} 是前端模板字符串的写法。
  3. 视图属性用 let 声明后又在 body 里试图修改 → 编译报错，需要改的状态要用 @State（见 L2 题目 1）。

题目 2 · 结构体与字符串插值（对应概念 02） ​

难度：基础

题目：定义 struct User（含 name: String、age: Int），写 formatUser(_ user: User) -> String 返回 "姓名(年龄)"，再写 adultNames(_ users: [User]) -> [String] 返回所有成年用户的名字。

要求：

  • User 用 struct（值类型），属性分别用 let 与 var 声明一次，体会区别
  • 用字符串插值 \(...) 拼接，不要用 +
  • 创建 3 个实例（含 1 个未成年），打印结果

提示：前端锚点——struct 类似「带类型的对象字面量」，但它是值类型（赋值即拷贝），这是与 JS 对象最大的差异。

参考答案
swift
import Foundation

// struct 是值类型：赋值/传参会拷贝（class 才是引用类型）
struct User {
    let name: String   // let：创建后不可改
    var age: Int       // var：可以被修改
}

func formatUser(_ user: User) -> String {
    "\(user.name)(\(user.age))"    // 单表达式函数可省略 return（Swift 5.1+）
}

func adultNames(_ users: [User]) -> [String] {
    users.filter { $0.age >= 18 }   // $0 是闭包第一个隐式参数
        .map { $0.name }
}

let users = [
    User(name: "Alice", age: 30),
    User(name: "Bob", age: 17),
    User(name: "Charlie", age: 25)
]

for user in users {
    print(formatUser(user))
}
// Alice(30)
// Bob(17)
// Charlie(25)

print(adultNames(users))   // ["Alice", "Charlie"]

// 值类型语义：拷贝后改副本不影响原值（与 JS 对象引用传递完全不同）
var a = User(name: "Dave", age: 40)
var b = a
b.age = 41
print(a.age)   // 40（原值没变）
print(b.age)   // 41

要点解析：

  1. let 是不可变绑定、var 可变；默认写 let，需要改才用 var。
  2. struct 是值类型：var b = a 是拷贝，改 b 不影响 a——前端习惯「改对象影响原引用」的直觉在这里不成立。
  3. 参数标签：函数定义 formatUser(_ user:) 里的 _ 表示调用时省略外部标签，写成 formatUser(user:) 则调用要带 user:。

常见错误：

  1. var x = 1; x = "a" → 类型推导后类型固定，编译报错（Swift 没有 JS 的动态切换）。
  2. 调用时写成 formatUser(user) 而函数声明没加 _ → 报「missing argument label 'user:'」。
  3. 以为改 struct 副本会影响原值 → 值类型拷贝语义，需要「改回去」得重新赋值。

题目 3 · switch 区间与 guard 提前退出（对应概念 02） ​

难度：基础

题目：写 func grade(_ score: Int) -> String：0-59「不及格」、60-79「及格」、80-89「良好」、90-100「优秀」，超出范围抛出自定义错误 ScoreError.outOfRange。

要求：

  • 等级判断用 switch + 区间（case 0..<60:）
  • 用 guard 做参数校验提前抛出（体会 Swift 的 early-exit 惯用法）
  • 写 5 个用例验证：45 / 60 / 85 / 100 / 101（最后一个要能捕获错误）

提示：前端锚点——switch 比 JS 的强大多了：能匹配区间、能模式匹配，且分支不贯穿（不用写 break）；guard 就是 early return 的语法糖。

参考答案
swift
import Foundation

enum ScoreError: Error {
    case outOfRange(Int)
}

func grade(_ score: Int) throws -> String {
    // guard：条件不成立就提前退出（else 分支必须 return / throw / break）
    guard score >= 0, score <= 100 else {
        throw ScoreError.outOfRange(score)
    }

    switch score {
    case 0..<60:   return "不及格"      // 半开区间：0-59，不含 60
    case 60..<80:  return "及格"        // 60-79
    case 80..<90:  return "良好"        // 80-89
    default:       return "优秀"        // 90-100（switch 必须穷尽，default 兜底）
    }
}

for score in [45, 60, 85, 100, 101] {
    do {
        let result = try grade(score)   // throws 函数必须用 try 调用
        print("\(score) -> \(result)")
    } catch ScoreError.outOfRange(let s) {
        print("\(score) -> 错误：分数必须在 0-100 之间，收到 \(s)")
    } catch {
        print("\(score) -> 其他错误：\(error)")
    }
}
// 45 -> 不及格
// 60 -> 及格
// 85 -> 良好
// 100 -> 优秀
// 101 -> 错误：分数必须在 0-100 之间，收到 101

要点解析：

  1. 区间有两种：0..<60 半开（不含 60）、0...60 闭区间（含 60）。Swift 用 ..< 表示「不含右端」，写错成 ... 会多包含一个数（判断 60 分时会落错档）。
  2. switch 必须穷尽所有情况（枚举可穷尽，Int 必须写 default）；分支默认不贯穿，不需要 break。
  3. guard 的 else 分支必须以 return / throw / break / continue 结束，否则编译报错——这是编译器强制你处理「失败路径」。

常见错误：

  1. switch 覆盖不全又不写 default → 编译报错「switch must be exhaustive」。
  2. guard ... else { print("x") } 后面继续写代码 → 编译报错，else 分支必须离开作用域。
  3. 调用 grade(101) 忘记写 try → 编译报错「call can throw but is not marked with 'try'」。

题目 4 · 集合链式处理（对应概念 03） ​

难度：基础

题目：给定用户数组，实现「过滤成年人 → 提取名字 → 拼接成逗号分隔的字符串」，并统计「所有成年用户名字的字符总数」。

要求：

  • 两个结果都用链式调用（filter / map / reduce）
  • 明确区分 let（不可变数组）与 var（可变数组）：数据源用 let，需要追加时再 var 拷贝一份
  • 打印两个结果

提示：前端锚点——filter{}.map{} 与 arr.filter().map() 一一对应，隐式参数是 $0/$1 而不是 (u) =>。

参考答案
swift
import Foundation

struct User {
    let name: String
    var age: Int
}

// let 声明的数组不可增删改（值类型语义）
let users: [User] = [
    User(name: "Alice", age: 30),
    User(name: "Bob", age: 17),
    User(name: "Charlie", age: 25),
    User(name: "Dave", age: 40)
]

// 1) 过滤 -> 提取 -> 拼接
let adultNameStr: String = users
    .filter { $0.age >= 18 }
    .map { $0.name }
    .joined(separator: ", ")
print(adultNameStr)   // Alice, Charlie, Dave

// 2) 过滤 -> 提取 -> 取长度 -> 累加
let totalLength: Int = users
    .filter { $0.age >= 18 }
    .map { $0.name }
    .map { $0.count }              // Swift 字符串长度用 .count
    .reduce(0) { $0 + $1 }         // reduce 需要给初始值
print(totalLength)    // 5 + 7 + 4 = 16

// 3) 需要修改时，先拷贝到 var（值类型：拷贝后改副本不影响原数组）
var mutableUsers = users
mutableUsers.append(User(name: "Eve", age: 22))
mutableUsers.removeFirst()
print(users.count)          // 4（原数组没变）
print(mutableUsers.count)   // 4

// 4) 不可变追加：+ 生成新数组
let added = users + [User(name: "Frank", age: 28)]
print(added.count)   // 5

要点解析：

  1. Array / Dictionary / Set 全是值类型（struct），赋值即拷贝；let 声明的集合完全不可改，var 才能 append。
  2. reduce(0) { $0 + $1 } 必须给初始值（不像 JS 的 reduce 可以省略），$0 是累加值、$1 是当前元素。
  3. 查找用 first(where:)，返回的是可选类型（见题目 8），不是元素本身。

常见错误：

  1. let users = [...]; users.append(...) → 编译报错「cannot use mutating member on immutable value」。
  2. var b = a; b.append(x) 后以为 a 也变了 → 值类型拷贝，原数组纹丝不动。
  3. 用 reduce { $0 + $1 } 不带初始值 → Swift 的 reduce 签名要求初始值（reduce(into:) 另有用法）。

题目 5 · 分组与计数（对应概念 03） ​

难度：进阶

题目：实现两个函数。

  1. groupByAgeRange(_ users:)：按「未成年（<18）/ 青年（18-44）/ 中年（>=45）」分组，返回 [String: [User]]。
  2. countTags(_ tags: [String]) -> [String: Int]：统计每个标签出现次数。

要求：

  • 第 1 题用 Dictionary(grouping:by:)，第 2 题手写循环（体会字典下标返回可选类型）
  • 打印每组的用户名字列表，以及标签计数结果

提示：前端锚点——Dictionary(grouping:) 相当于 lodash 的 groupBy；countTags 就是 JS 里 reduce 手搓计数的字典版本。

参考答案
swift
import Foundation

struct User {
    let name: String
    var age: Int
}

func groupByAgeRange(_ users: [User]) -> [String: [User]] {
    Dictionary(grouping: users) { user in
        switch user.age {
        case 0..<18:  return "未成年"
        case 18..<45: return "青年"
        default:      return "中年"
        }
    }
}

func countTags(_ tags: [String]) -> [String: Int] {
    var result: [String: Int] = [:]
    for tag in tags {
        // 字典下标返回 Int?（首次为 nil），?? 给默认值 0
        result[tag] = (result[tag] ?? 0) + 1
    }
    return result
}

let users = [
    User(name: "Alice", age: 30),
    User(name: "Bob", age: 17),
    User(name: "Charlie", age: 45),
    User(name: "Dave", age: 22)
]

let grouped = groupByAgeRange(users)
for (range, list) in grouped {
    print("\(range): \(list.map { $0.name })")
}
// 青年: ["Alice", "Charlie"] 之外的顺序不确定（字典无序）
// 未成年: ["Bob"]
// 中年: ["Charlie"]

let tags = ["js", "ts", "js", "go", "ts", "js"]
print(countTags(tags))   // ["js": 3, "ts": 2, "go": 1]（顺序不确定）

要点解析：

  1. Dictionary(grouping:by:) 是标准库分组函数；字典是无序的，遍历顺序不要依赖（需要稳定顺序就 sorted(by:)）。
  2. 字典下标访问返回 V?——「键不存在」和「值是 nil」都表现为 nil，所以 (result[tag] ?? 0) + 1 是标准写法。
  3. 计数场景标准库也提供了 tags.reduce(into: [:]) { counts, tag in counts[tag, default: 0] += 1 }，用 default: 下标更地道。

常见错误：

  1. result[tag] + 1 → 可选类型参与运算，编译报错。
  2. 依赖字典遍历顺序做业务逻辑 → 字典无序，每次运行顺序可能不同。
  3. switch 里用 case 0...17 与 case 18...44 混写导致边界重叠（18 会被第一个匹配）→ 区间边界要对齐，用 ..< 更安全。

题目 6 · 第一个 async/await（对应概念 04） ​

难度：进阶

题目：实现 func fetchUser(id: Int) async throws -> User，内部 Task.sleep 挂起 1 秒模拟网络请求，然后在 Task { } 里调用并打印结果。

要求：

  • 函数标记为 async throws（既异步又可能失败）
  • 调用必须写 try await，并用 do-catch 处理错误
  • 打印「开始请求」→（1 秒后）→「获取到：User1」

提示：前端锚点——Swift 的 async/await 与 JS 语法几乎一致；差异是 Swift 用 Task {} 启动异步上下文（≈ async IIFE），Task.sleep 不阻塞线程（≈ await sleep）。

参考答案
swift
import Foundation

struct User {
    let name: String
    let age: Int
    let friendId: Int
}

// async throws：可挂起 + 可能抛错
func fetchUser(id: Int) async throws -> User {
    try await Task.sleep(nanoseconds: 1_000_000_000)   // 挂起 1 秒（1 秒 = 10 亿纳秒）
    return User(name: "User\(id)", age: 20 + id, friendId: 1)
}

// Task {} 启动异步上下文（类比 async IIFE），在非 async 环境里调用 async 函数的入口
Task {
    print("开始请求")
    do {
        let user = try await fetchUser(id: 1)   // try + await 成对出现
        print("获取到：\(user.name)，\(user.age) 岁")
    } catch {
        print("请求失败：\(error)")
    }
}
// 输出：
// 开始请求
// （约 1 秒后）
// 获取到：User1，21 岁

要点解析：

  1. async 函数只能在 async 上下文或 Task {} 里调用；throws 函数必须用 try 调用，两者叠加就是 try await。
  2. Task.sleep(nanoseconds:) 的单位是纳秒（1 秒 = 1_000_000_000），下划线分隔数字是 Swift 的可读性写法。
  3. Task {} 启动的是非结构化任务（不随父作用域自动取消），写业务时优先 async let 或 withTaskGroup。

常见错误：

  1. 在非 async 的普通函数里直接 await fetchUser(...) → 编译报错「'async' call in a function that does not support concurrency」。
  2. 忘记写 try → 编译报错；忘记写 await → 同样报错（编译器会提示补全）。
  3. 把 Task.sleep 的纳秒写成 1000（当成毫秒）→ 只睡了 1 微秒，看起来像「没延迟」。

题目 7 · 并发获取多个用户（对应概念 04） ​

难度：进阶

题目：实现 func getUsers(ids: [Int]) async throws -> [User]，用 withThrowingTaskGroup 并发获取所有用户，并打印耗时；再用 async let 写两个用户并发的版本，对比 JS 的 Promise.all。

要求：

  • 任务组版本：用 group.addTask {} 启动、for try await 收集结果
  • async let 版本：同时启动两个请求，用 try await (a, b) 等待
  • 打印并发耗时，说明为什么总耗时不是 ids.count × 1 秒

提示：前端锚点——TaskGroup ≈ Promise.all 的通用版，async let ≈ 先发起 Promise、稍后 await 的语法糖（Swift 独有）。

参考答案
swift
import Foundation

struct User {
    let name: String
    let age: Int
    let friendId: Int
}

func fetchUser(id: Int) async throws -> User {
    try await Task.sleep(nanoseconds: 1_000_000_000)
    return User(name: "User\(id)", age: 20 + id, friendId: 1)
}

// 方案一：TaskGroup（结构化并发，适合数量不固定的并发任务）
func getUsers(ids: [Int]) async throws -> [User] {
    try await withThrowingTaskGroup(of: User.self) { group in
        for id in ids {
            group.addTask { try await fetchUser(id: id) }   // 并发启动
        }
        var results: [User] = []
        // 按「完成顺序」收集（不是 ids 顺序！需要顺序用 enumerated + 排序）
        for try await user in group {
            results.append(user)
        }
        return results
    }
}

// 方案二：async let（Swift 独有的并发绑定，适合固定数量的并发任务）
func loadTwoUsers() async throws -> (User, User) {
    async let user1 = fetchUser(id: 1)   // 立即并发启动
    async let user2 = fetchUser(id: 2)   // 立即并发启动
    return try await (user1, user2)      // 在此处等待（类比 await Promise.all）
}

Task {
    let start = Date()
    let users = try await getUsers(ids: [1, 2, 3])
    print("并发获取 \(users.count) 个用户，耗时 \(Date().timeIntervalSince(start)) 秒")
    // 并发获取 3 个用户，耗时约 1.0 秒（三个任务同时跑，不是 3 秒）

    let (a, b) = try await loadTwoUsers()
    print("\(a.name), \(b.name)")
}

要点解析：

  1. async let 声明时不阻塞，真正等待发生在 await 那一行——两个请求是同时发出去的。
  2. withThrowingTaskGroup 是结构化并发：作用域结束时所有子任务要么完成、要么被取消，不会泄漏（对比 Task {} 的非结构化）。
  3. TaskGroup 的 for try await 按完成顺序产出，若需要保持入参顺序，要自己带下标再排序。

常见错误：

  1. 写成 for id in ids { results.append(try await fetchUser(id: id)) } → 这是串行，耗时 = N 秒。
  2. 在 async let 声明后没有 await 就离开作用域 → 编译器警告/错误（未等待的 async let 会被自动取消）。
  3. 用 Task {} 批量启动任务却不保存句柄 → 非结构化任务，无法取消、无法拿到结果。

题目 8 · Optional 安全解包（对应概念 05） ​

难度：基础

题目：实现 findUser(_ users:name:) -> User?（找不到返回 nil），再写 describe(_ users:name:) -> String：找到时返回 "姓名(年龄)"，找不到返回 "查无此人"。

要求：

  • 分别用 if let 与 guard let 各写一遍，体会两者适用场景
  • 不允许出现强制解包 !
  • 覆盖两种情形：找得到、找不到，都要打印验证

提示：前端锚点——Optional ≈ TS 的 T | undefined，但 Swift 在编译期强制你处理；if let ≈ if (x) 收窄，?? 与 JS 完全一致。

参考答案
swift
import Foundation

struct User {
    let name: String
    let age: Int
}

// 返回可选类型 User?：找不到返回 nil
func findUser(_ users: [User], name: String) -> User? {
    users.first { $0.name == name }   // first(where:) 返回 Optional
}

// 写法一：if let —— 在条件块内解包
func describeWithIfLet(_ users: [User], name: String) -> String {
    if let user = findUser(users, name: name) {
        return "\(user.name)(\(user.age))"   // 块内 user 已是非空 User
    } else {
        return "查无此人"
    }
}

// 写法二：guard let —— 提前退出，主体代码全程用非空值
func describeWithGuard(_ users: [User], name: String) -> String {
    guard let user = findUser(users, name: name) else {
        return "查无此人"       // else 分支必须 return / throw / break
    }
    return "\(user.name)(\(user.age))"   // 此后 user 恒为非空
}

let users = [User(name: "Alice", age: 30), User(name: "Bob", age: 17)]
print(describeWithIfLet(users, name: "Alice"))    // Alice(30)
print(describeWithGuard(users, name: "Zoe"))      // 查无此人

// 其他常用写法
let nickname: String? = nil
print(nickname?.uppercased() as Any)   // nil（可选链，不崩溃）
print(nickname ?? "匿名")               // 匿名（空值合并，与 JS ?? 一致）
print(nickname?.count ?? 0)             // 0

要点解析：

  1. Optional 是枚举（some / none），? 只是语法糖；不解包就不能访问内部值，这是编译期的强制保护。
  2. if let 适合「两种分支都要处理」；guard let 适合「不满足就退出，主体逻辑用解包后的值」，能减少嵌套。
  3. ?? 与 ?. 的行为和 JS 完全一致，差别在于 Swift 只有 nil（没有 undefined）。

常见错误：

  1. 直接 user.name → 编译报错「value of optional type 'User?' must be unwrapped」。
  2. 用 user!.name 图省事 → 未找到时运行时崩溃，! 在生产代码里等同于埋雷。
  3. guard let 的 else 分支里只 print 不 return → 编译报错「'guard' body must not fall through」。

题目 9 · do-catch 与自定义错误（对应概念 05） ​

难度：基础

题目：定义 enum MathError: Error { case divideByZero }，实现 divide(_ a:b:) throws -> Int（除数为 0 时 throw MathError.divideByZero）；调用方用 do-catch 分分支捕获，并在 defer 里打印「计算结束」。

要求：

  • catch 分支要分具体错误 + 兜底两层
  • 用 defer 验证「无论成功失败都会执行」
  • 额外演示 try? 与 try! 的区别（并说明 try! 为什么危险）

提示：前端锚点——Swift 的 do-catch 与 JS 的 try/catch 不同点在于：throwing 函数必须用 try 标记调用点，catch 必须穷尽（编译期检查）。

参考答案
swift
import Foundation

enum MathError: Error {
    case divideByZero
}

// throws 函数：可能失败，调用点必须写 try
func divide(_ a: Int, _ b: Int) throws -> Int {
    guard b != 0 else { throw MathError.divideByZero }   // guard + throw 是校验惯用法
    return a / b
}

func safeDivide(_ a: Int, _ b: Int) -> Int {
    do {
        defer { print("计算结束") }   // defer：作用域结束时必定执行（成功失败都执行）
        return try divide(a, b)
    } catch MathError.divideByZero {
        print("捕获到：除数不能为零")
        return 0
    } catch {
        print("捕获到其他错误：\(error)")
        return 0
    }
}

print(safeDivide(10, 2))   // 计算结束 → 5
print(safeDivide(10, 0))   // 捕获到：除数不能为零 → 计算结束 → 0

// try? ：失败时返回 nil（把错误「降级」成可选值）
let ok: Int? = try? divide(10, 2)    // Optional(5)
let bad: Int? = try? divide(10, 0)   // nil

// try! ：失败直接崩溃 —— 只在「100% 确定不会失败」时用，生产代码基本不用
// let crash = try! divide(10, 0)    // 运行时崩溃

要点解析：

  1. throws 声明把「可能失败」写进类型系统，调用点必须显式 try——调用方无法假装没看见错误。
  2. try? 把错误转成 nil（适合「失败就当没有」的场景），try! 把错误转成崩溃（除非写测试或字面量常量，否则别用）。
  3. defer 块在离开作用域时执行，常用于「配对的资源释放」（关文件、解锁），等价于 JS 的 finally 但写在使用处附近。

常见错误：

  1. 调用 divide(10, 0) 忘记 try → 编译报错「call can throw but is not marked with 'try'」。
  2. catch 里只写 print 不返回值 → 若函数要求返回 Int，两个分支的返回类型要一致。
  3. 到处用 try! → 一旦线上出现意外输入就直接崩溃，是崩溃率的主要来源之一。

题目 10 · 综合：带超时重试的安全查询（对应概念 04 + 05） ​

难度：综合

题目：实现 func safeGetUser(id: Int) async -> String，串联空安全、错误处理与并发：

  1. ID 小于等于 0 → 抛 UserError.invalidId
  2. 用 withTimeout 包住 fetchUser，超时 2 秒后重试，最多 3 次
  3. 3 次都失败 → 返回 "未找到用户（已重试 3 次）"，不崩溃、不静默
  4. 成功 → 返回 "找到：User1"

要求：

  • withTimeout 用 withThrowingTaskGroup 实现（业务任务 vs 睡眠任务竞速，拿到结果后 cancelAll()）
  • 每次失败都打印原因
  • 全程不使用 ! / try!
  • 验证两种输入：1（成功）、-1（抛参数错误，用 do-catch 兜住）

提示：前端锚点——这就是 Promise.race([fetch(), timeout(2000)]) + 重试循环 + TS 严格空检查的合体；Swift 版靠 TaskGroup 竞速实现。

参考答案
swift
import Foundation

struct User {
    let name: String
    let age: Int
    let friendId: Int
}

enum UserError: Error {
    case invalidId(Int)
    case timeout
}

// 超时包装：业务任务与「睡眠任务」竞速，谁先返回用谁，随后取消另一个
func withTimeout<T>(seconds: UInt64, operation: @escaping () async throws -> T) async throws -> T {
    try await withThrowingTaskGroup(of: T.self) { group in
        group.addTask { try await operation() }          // 业务任务
        group.addTask {
            try await Task.sleep(nanoseconds: seconds * 1_000_000_000)
            throw UserError.timeout                      // 睡够时间就抛超时
        }
        // next() 拿到第一个完成的结果（成功或抛出）
        guard let result = try await group.next() else {
            throw UserError.timeout
        }
        group.cancelAll()   // 关键：取消还没跑完的那个任务，避免泄漏
        return result
    }
}

// 模拟网络请求：id 为 999 时「慢到超时」
func fetchUser(id: Int) async throws -> User {
    try await Task.sleep(nanoseconds: UInt64(id == 999 ? 3 : 1) * 1_000_000_000)
    return User(name: "User\(id)", age: 20 + id, friendId: 1)
}

// 带重试的获取：三次都失败返回 nil（用可选类型表达「没有结果」）
func fetchWithRetry(id: Int, maxRetry: Int = 3) async -> User? {
    for attempt in 1...maxRetry {
        do {
            return try await withTimeout(seconds: 2) { try await fetchUser(id: id) }
        } catch UserError.timeout {
            print("第 \(attempt) 次请求超时，准备重试")
        } catch {
            print("第 \(attempt) 次请求失败：\(error)")
        }
    }
    return nil
}

func safeGetUser(id: Int) async throws -> String {
    guard id > 0 else { throw UserError.invalidId(id) }   // 参数校验：guard + throw
    let user = await fetchWithRetry(id: id)
    // 可选链 + 空值合并：把「没有结果」翻译成友好文案
    return user.map { "找到：\($0.name)" } ?? "未找到用户（已重试 3 次）"
}

Task {
    do {
        print(try await safeGetUser(id: 1))      // 找到：User1
        print(try await safeGetUser(id: 999))
        // 第 1 次请求超时，准备重试
        // 第 2 次请求超时，准备重试
        // 第 3 次请求超时，准备重试
        // 未找到用户（已重试 3 次）
        _ = try await safeGetUser(id: -1)
    } catch UserError.invalidId(let bad) {
        print("参数错误：ID 必须为正数，收到 \(bad)")
    } catch {
        print("其他错误：\(error)")
    }
}

要点解析：

  1. 用类型表达结果：「可能没有」用 User?；「调用方传错了」用 throw。前者是正常业务分支，后者是调用方的责任。
  2. TaskGroup 竞速后必须 cancelAll()：否则超时的请求仍在后台跑，白占资源（结构化并发会在作用域结束时自动等待，不取消就白等）。
  3. guard id > 0 else { throw ... } 是 Swift 参数校验的标准写法，比手写 if 更贴近「happy path 直行」的阅读顺序。

常见错误：

  1. 竞速拿到结果后忘记 cancelAll() → 慢任务继续跑完，浪费连接与内存。
  2. 重试失败时返回「假 User」（如空名字对象）→ 调用方无法区分「查无此人」与「请求失败」，应该用 nil 或 Result。
  3. 用 try! 或 user!.name 省事 → 线上遇到意外输入就崩溃，与「不崩溃」的要求直接冲突。
