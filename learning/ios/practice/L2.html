覆盖概念：06 声明式 UI 思想 · 07 布局系统 · 08 组件化与复用 · 09 状态管理 · 10 列表渲染与虚拟滚动 · 11 导航与路由 · 12 表单与用户输入 对应等级：L2 基础能力者（能力目标见 levels.md） 使用方式：先自己写完，再对答案。用 /practice ios L2 可让 AI 陪练抽取题目并做代码评审。

题目 1 · 计数器：@State 驱动视图（对应概念 06） ​

难度：基础

题目：实现一个计数器：屏幕中间显示当前数字（较大字号），下方「+1」按钮加一、「重置」按钮归零。

要求：

  • 状态用 @State private var count = 0
  • body 是计算属性，必须保持轻量、无副作用
  • 不要出现任何「手动改视图」的代码（SwiftUI 里没有 label.text = ...）

提示：前端锚点——@State ≈ useState，改状态 → SwiftUI 重新求值 body → diff 后更新视图；body 就是 render 函数。

参考答案
swift
import SwiftUI

struct Counter: View {
    @State private var count = 0   // 视图私有的可观察状态，变化触发 body 重算

    var body: some View {
        VStack(spacing: 16) {
            Text("当前计数：\(count)")
                .font(.system(size: 40, weight: .bold))

            HStack(spacing: 12) {
                Button("+1") { count += 1 }              // 改状态，视图自动更新
                    .buttonStyle(.borderedProminent)
                Button("重置") { count = 0 }
                    .buttonStyle(.bordered)
            }
        }
        .frame(maxWidth: .infinity, maxHeight: .infinity)   // 撑满整屏并居中
    }
}

要点解析：

  1. @State 是属性包装器，标记「这是视图私有的可观察状态」；写成普通 var count = 0 改了不会刷新视图（struct 的 let/var 本身不可被 SwiftUI 观察）。
  2. body 是计算属性，每次访问都重新求值，所以必须轻量、无副作用（不要在 body 里发请求、写文件、改全局变量）。
  3. 调试思路是「找状态为什么变了」，而不是「找谁改了视图」——命令式转声明式的核心切换。

常见错误：

  1. var count = 0 后 count += 1 → 编译直接报错（self 不可变），或改成 @State 才能工作。
  2. 不用 private 修饰 → 不是错误，但 @State 应当视图私有；跨视图共享要用 @Binding / @EnvironmentObject（题目 6）。
  3. 在 body 里写 print 之外的副作用（如 URLSession 请求）→ 每次重算都触发，请求风暴。

题目 2 · 待办最小原型（对应概念 06） ​

难度：进阶

题目：用声明式思维实现「待办添加 + 列表显示」：一个输入框、一个「添加」按钮，下方逐行显示已添加的待办。

要求：

  • 先列状态（输入文本、待办数组），再写 UI，最后加事件
  • 输入为空（含纯空格）时点击「添加」不产生空条目
  • 添加成功后清空输入框
  • 更新数组用 append（@State 数组是 var，值类型变更会触发刷新）

提示：前端锚点——@State private var todos: [String] = [] + 受控 input；SwiftUI 用 $input 双向绑定，比 React 的 value + onChange 少写一半代码。

参考答案
swift
import SwiftUI

struct TodoMini: View {
    @State private var input = ""            // 输入框内容（双向绑定）
    @State private var todos: [String] = []  // 待办列表

    var body: some View {
        VStack(spacing: 12) {
            HStack {
                // $input 是 @State 的双向绑定投影（类比 v-model）
                TextField("想做点什么", text: $input)
                    .textFieldStyle(.roundedBorder)
                Button("添加") {
                    let text = input.trimmingCharacters(in: .whitespaces)
                    guard !text.isEmpty else { return }   // 空格不算有效输入
                    todos.append(text)
                    input = ""
                }
                .buttonStyle(.borderedProminent)
            }

            // 状态映射成视图：数组有几条就渲染几个 Text
            VStack(alignment: .leading, spacing: 6) {
                ForEach(todos.indices, id: \.self) { index in
                    Text("• \(todos[index])")
                }
            }
            .frame(maxWidth: .infinity, alignment: .leading)

            Spacer()   // 弹性占位，把内容顶到顶部
        }
        .padding()
    }
}

要点解析：

  1. $input 是 @State 的双向绑定投影：TextField(text: $input) 直接把用户输入写回状态，不用手写 onChange。
  2. guard !text.isEmpty else { return } 是提前退出惯用法，比嵌套 if 更清晰；trimmingCharacters(in: .whitespaces) 挡住纯空格输入。
  3. ForEach(todos.indices, id: \.self) 依赖下标做 id——仅演示用；数据会增删时下标会错位，应该用 Identifiable（题目 7）。

常见错误：

  1. TextField("...", text: input) 忘了 $ → 编译报错（需要 Binding<String> 而非 String）。
  2. 用 if input != "" 但没 trim → 输入空格也能添加空条目。
  3. 把 todos 声明成 let 常量后调用 append → 编译报错，状态必须是 var。

题目 3 · 三段式布局（对应概念 07） ​

难度：基础

题目：实现「顶部标题 + 中间内容 + 底部按钮」的三段式布局：标题在最上，按钮吸底，中间内容吃掉所有剩余空间并居中。

要求：

  • 用 VStack + Spacer() 撑开中间区域
  • 按钮宽度占满（.frame(maxWidth: .infinity)）
  • 整屏内边距 16pt

提示：前端锚点——VStack = flex-direction: column，Spacer() = flex-grow: 1 的空白元素，spacing = gap。

参考答案
swift
import SwiftUI

struct ThreeSectionLayout: View {
    var body: some View {
        VStack(spacing: 16) {
            Text("页面标题")
                .font(.title)
                .frame(maxWidth: .infinity, alignment: .leading)   // 标题左对齐

            // Spacer() 会吃掉所有剩余空间，把下面的按钮顶到底部
            Spacer()

            Text("中间内容区域")
                .foregroundColor(.gray)

            Spacer()

            Button("提交") { /* 提交操作 */ }
                .buttonStyle(.borderedProminent)
                .frame(maxWidth: .infinity)   // 类比 width: 100%
        }
        .padding(16)
        .frame(maxWidth: .infinity, maxHeight: .infinity)   // 撑满整屏
    }
}

要点解析：

  1. SwiftUI 没有直接的「主轴对齐」参数：VStack 默认居中分布，想要 space-between 效果就在元素间插 Spacer()（这是与 CSS 最大的手感差异）。
  2. spacing 参数等价于 gap；alignment 参数等价于 align-items（.leading / .center / .trailing）。
  3. Spacer() 会无限撑开：两个 Spacer() 平分剩余空间（所以内容居中），用 Spacer().frame(height: 24) 才是固定间距。

常见错误：

  1. 忘了外层 .frame(maxHeight: .infinity) → Spacer() 没有可撑开的空间，按钮不会吸底。
  2. 想用 justifyContent 之类的参数 → HStack/VStack 没有这个参数，要用 Spacer()。
  3. 放了三个 Spacer() 期望等距 → 它们会平分空间且逻辑混乱，间距请用 spacing。

题目 4 · 横向卡片与层叠（对应概念 07） ​

难度：进阶

题目：实现一个消息卡片：左侧 40pt 圆形头像占位，中间标题 + 副标题（占满剩余宽度、副标题单行省略），右侧灰色时间（不被压缩）；头像右上角叠一个红色「未读」小红点。

要求：

  • 用 HStack(spacing: 12)，中间 VStack 用 .frame(maxWidth: .infinity, alignment: .leading)
  • 时间文字用 .fixedSize() 防止被压缩
  • 红点用 ZStack + .offset 或 .overlay 叠在头像右上角

提示：前端锚点——HStack = flex-direction: row，ZStack = position: relative + 绝对定位子元素；层级由书写顺序决定（后写的在上），没有 z-index。

参考答案
swift
import SwiftUI

struct MessageCard: View {
    let title: String
    let subtitle: String
    let time: String
    let unread: Bool

    var body: some View {
        HStack(spacing: 12) {
            // 层叠：头像 + 右上角红点（用 overlay 叠加，等价 ZStack）
            Circle()
                .fill(Color.gray.opacity(0.3))
                .frame(width: 40, height: 40)
                .overlay(alignment: .topTrailing) {
                    if unread {
                        Circle()
                            .fill(Color.red)
                            .frame(width: 10, height: 10)
                            .offset(x: 2, y: -2)   // 微调偏移，露出一点在头像外
                    }
                }

            // 中间区域占满剩余宽度（frame + alignment 是 SwiftUI 的 flex: 1）
            VStack(alignment: .leading, spacing: 2) {
                Text(title)
                    .fontWeight(.semibold)
                    .lineLimit(1)
                Text(subtitle)
                    .font(.subheadline)
                    .foregroundColor(.gray)
                    .lineLimit(1)          // 超出显示 ...
            }
            .frame(maxWidth: .infinity, alignment: .leading)

            // fixedSize：优先保证时间完整显示，不被中间内容挤扁
            Text(time)
                .font(.caption)
                .foregroundColor(.gray)
                .fixedSize()
        }
        .padding(16)
    }
}

要点解析：

  1. SwiftUI 的「占满剩余」是 .frame(maxWidth: .infinity)；多个元素都设就均分（类比 CSS 里多个 flex: 1），想按不同比例分配要用 .layoutPriority()。
  2. ZStack 与 .overlay 都能做层叠：ZStack 适合整块内容叠放，.overlay / .background 适合相对某个视图定位——二者都遵循「后写的在上」。
  3. .fixedSize() 让视图保持固有尺寸不被压缩，常用于「时间、金额、标签」这类必须完整显示的元素。

常见错误：

  1. 中间 VStack 忘了 frame(maxWidth: .infinity, alignment: .leading) → 副标题过长会把时间挤出屏幕，且文字默认居中。
  2. 想用 .frame(maxWidth: .infinity) 做 1:2 比例 → 两个都设会均分，比例要用 .layoutPriority()（不如 CSS 的 flex: n 直观）。
  3. 到处放 Spacer() 做间距 → Spacer() 会无限撑开，多个并存容易撑爆布局；固定间距用 spacing。

题目 5 · 可复用卡片与 ViewModifier（对应概念 08） ​

难度：进阶

题目：封装一个泛型 Card<Content: View> 组件：接收 title 和一个 @ViewBuilder 内容插槽，负责标题样式、内边距与卡片外观；再用 ViewModifier 抽出「卡片样式」供其他地方复用。

要求：

  • 插槽用 @ViewBuilder let content: () -> Content，组件声明 <Content: View>
  • 调用时用尾随闭包语法 Card(title: "...") { ... }
  • 用 ViewModifier + extension View 提供 .cardStyle() 修饰

提示：前端锚点——@ViewBuilder 闭包 ≈ React 的 children，泛型 <Content: View> ≈ TS 泛型组件，ViewModifier ≈ 打包复用的 CSS 类。

参考答案
swift
import SwiftUI

// 泛型组件：<Content: View> 让插槽内容类型灵活
struct Card<Content: View>: View {
    let title: String
    @ViewBuilder let content: () -> Content   // 插槽：@ViewBuilder 允许写多个子视图

    var body: some View {
        VStack(alignment: .leading, spacing: 8) {
            Text(title)
                .font(.title3)
                .fontWeight(.semibold)
            content()        // 在此处插入调用方传入的内容
        }
        .cardStyle()         // 复用抽出的样式
    }
}

// 样式复用：ViewModifier 把一组修饰打包
struct CardStyle: ViewModifier {
    func body(content: Content) -> some View {
        content
            .padding(16)
            .frame(maxWidth: .infinity, alignment: .leading)
            .background(Color.gray.opacity(0.1))
            .cornerRadius(8)
    }
}

extension View {
    func cardStyle() -> some View { modifier(CardStyle()) }
}

// 使用：尾随闭包语法，像 JSX 一样自然
struct ProfileScreen: View {
    var body: some View {
        VStack(spacing: 12) {
            Card(title: "基本信息") {
                Text("姓名：Claude")
                Text("年龄：30")
            }
            Card(title: "联系方式") {
                Text("邮箱：claude@example.com")
            }
            Text("这段文字也复用卡片样式")
                .cardStyle()
        }
        .padding()
    }
}

要点解析：

  1. @ViewBuilder 让闭包内的多个子视图隐式组合（不用手写容器）；它有 10 个子视图的上限，超过要包 Group 或 VStack。
  2. 尾随闭包 Card(title: "...") { ... } 让 SwiftUI 的组件调用看起来和 JSX 一样直观。
  3. ViewModifier 的修饰顺序影响结果：.padding().background() 与 .background().padding() 效果完全不同（链式调用是从内到外逐层包装）。

常见错误：

  1. 忘记写泛型 <Content: View> → 编译报错（闭包返回的视图类型无法静态确定）。
  2. 在 @ViewBuilder 闭包里写超过 10 个子视图 → 编译报错，要分组。
  3. 把 .cardStyle() 写在 .frame(maxWidth:) 之后导致宽度计算异常 → 修饰顺序敏感，尺寸类修饰通常放最外层。

题目 6 · @Binding 与状态提升（对应概念 09） ​

难度：进阶

题目：把题目 1 的计数器拆成两层：父视图 CounterScreen 持有 @State private var count，子视图 CounterView 用 @Binding var count: Int 接收（无自有状态）；页面上放两个 CounterView，共享同一个计数。

要求：

  • 父传子用 $count（$ 取绑定引用）
  • 两个子视图任一操作，数字都同步变化
  • 能说清「@State 与 @Binding 的分工」

提示：前端锚点——@Binding + $ ≈ Vue 的 v-model，也 ≈ React 的「状态提升 + 受控 props + 回调」；Swift 的写法更简洁。

参考答案
swift
import SwiftUI

// 父视图：拥有状态（唯一真相源）
struct CounterScreen: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 20) {
            // $count 取 Binding 引用传给子视图
            CounterView(count: $count, step: 1)
            CounterView(count: $count, step: -1)
        }
        .frame(maxWidth: .infinity, maxHeight: .infinity)
    }
}

// 子视图：无自有状态，通过 @Binding 读写父级状态
struct CounterView: View {
    @Binding var count: Int
    let step: Int

    var body: some View {
        HStack(spacing: 12) {
            Text("计数：\(count)")
                .font(.title2)
            Button(step > 0 ? "+1" : "-1") {
                count += step   // 改的是父级状态（引用，不是拷贝）
            }
            .buttonStyle(.bordered)
        }
    }
}

要点解析：

  1. 分工：@State 在拥有状态的视图（创建处），@Binding 在使用状态的子视图（接收处），传值时用 $ 取引用。
  2. @Binding 是「引用」而非拷贝：子视图改 count 直接写回父级源，因此两个子视图天然同步。
  3. 对照 @StateObject / @ObservedObject（对象级状态）：@StateObject 用于创建处，@ObservedObject 用于接收处，混用会导致对象被重复创建。

常见错误：

  1. 子视图也写 @State private var count → 父子两份独立状态，点了不同步（L2 最典型的状态 bug）。
  2. 传值时忘了 $ → 编译报错（需要 Binding<Int> 却给了 Int）。
  3. 把 @Binding 属性给默认值再从父级传 → @Binding 不能初始化（必须父传），给了默认值就失去绑定意义。

题目 7 · List 渲染与滑动删除（对应概念 10） ​

难度：进阶

题目：用 List 渲染 100 条用户数据（头像占位 + 姓名 + 年龄），支持左滑删除某一行。

要求：

  • 数据模型遵循 Identifiable（必须有 id）
  • 删除用 .onDelete { indexSet in ... }
  • 列表状态由父视图持有（@State private var users）

提示：前端锚点——List 自带懒加载（不用装 react-window），Identifiable 相当于编译期强制的 key（比 React 的运行时 warning 严格得多）。

参考答案
swift
import SwiftUI

// Identifiable 是编译期强制的：没有 id 编译不过（相当于强制要求 key）
struct Person: Identifiable {
    let id: Int
    var name: String
    var age: Int
}

struct UserListScreen: View {
    @State private var users: [Person] = (1...100).map {
        Person(id: $0, name: "用户\($0)", age: 18 + $0 % 30)
    }

    var body: some View {
        List {
            ForEach(users) { user in     // ForEach + Identifiable，自动取 id 做 key
                UserRow(user: user)
            }
            .onDelete { indexSet in
                // remove(atOffsets:) 一次性删除，避免逐个删除时下标错位
                users.remove(atOffsets: indexSet)
            }
        }
        .listStyle(.plain)
    }
}

struct UserRow: View {
    let user: Person

    var body: some View {
        HStack(spacing: 12) {
            Circle()
                .fill(Color.gray.opacity(0.3))
                .frame(width: 40, height: 40)
            VStack(alignment: .leading, spacing: 2) {
                Text(user.name)
                Text("\(user.age) 岁")
                    .font(.caption)
                    .foregroundColor(.gray)
            }
        }
        .padding(.vertical, 4)
    }
}

要点解析：

  1. List 默认懒加载，ForEach 配 List 就是虚拟滚动；ScrollView { VStack { ForEach } } 会一次性渲染全部，数据量大必须用 List 或 LazyVStack。
  2. Identifiable 是编译期强制的 key：删除、动画、复用都靠它。用下标（ForEach(users.indices, id: \.self)）在增删时会错位。
  3. .onDelete 拿到的是 IndexSet，用 remove(atOffsets:) 一次性删除——循环里逐个 remove(at:) 会让后续下标失效。

常见错误：

  1. 模型没遵循 Identifiable 也没传 id 参数 → 编译报错。
  2. 用 ScrollView + VStack + ForEach 渲染 1000 条 → 全部一次性创建，内存暴涨、滚动卡顿。
  3. 在 onDelete 里 for i in indexSet { users.remove(at: i) } → 删第一个后下标整体前移，删错数据。

题目 8 · 列表页跳详情页 + 模态编辑（对应概念 11） ​

难度：进阶

题目：用 NavigationStack 实现「用户列表 → 用户详情 → 返回」；详情页再加一个「编辑昵称」按钮，点击弹出 .sheet 模态页，输入新昵称保存后关闭并更新详情显示。

要求：

  • 跳转用 NavigationLink(value:) + .navigationDestination(for:)
  • 参数用值类型传递（Int），体会类型安全路由
  • 模态用 .sheet(isPresented:)，关闭通过修改 @State 布尔值
  • 编辑后的昵称要能在详情页立刻看到

提示：前端锚点——NavigationStack ≈ <Routes> 的栈模型，NavigationLink(value:) ≈ <Link>；移动端没有 URL，「页面栈」就是路由状态。sheet ≈ 第三方 Modal 组件。

参考答案
swift
import SwiftUI

struct Person: Identifiable {
    let id: Int
    var name: String
}

struct ContentView: View {
    @State private var users = [
        Person(id: 1, name: "Alice"),
        Person(id: 2, name: "Bob"),
        Person(id: 3, name: "Charlie")
    ]

    var body: some View {
        NavigationStack {
            List(users) { user in
                // NavigationLink(value:) 是类型安全路由：value 的类型决定目的地
                NavigationLink(value: user.id) {
                    Text(user.name)
                }
            }
            .navigationTitle("用户列表")
            // 路由表：按 value 的类型匹配目的地（Int.self）
            .navigationDestination(for: Int.self) { userId in
                if let index = users.firstIndex(where: { $0.id == userId }) {
                    // 传 Binding：详情页的修改直接写回数组
                    DetailView(user: $users[index])
                }
            }
        }
    }
}

struct DetailView: View {
    @Binding var user: Person          // Binding：改动写回父级数据源
    @State private var showEditor = false   // 控制 sheet 的开关状态

    var body: some View {
        VStack(spacing: 16) {
            Text("用户详情页")
                .font(.title)
            Text("昵称：\(user.name)")
            Button("编辑昵称") { showEditor = true }
                .buttonStyle(.borderedProminent)
        }
        .navigationTitle(user.name)
        .sheet(isPresented: $showEditor) {
            NicknameEditor(name: $user.name)   // 模态页：同样用 Binding 回写
        }
    }
}

struct NicknameEditor: View {
    @Binding var name: String
    @Environment(\.dismiss) private var dismiss   // 关闭当前模态页

    var body: some View {
        VStack(spacing: 16) {
            TextField("新昵称", text: $name)
                .textFieldStyle(.roundedBorder)
                .padding()
            Button("保存") { dismiss() }   // 调用 dismiss 关闭 sheet
                .buttonStyle(.borderedProminent)
        }
        .padding()
    }
}

要点解析：

  1. NavigationLink(value:) 是类型安全路由：用值类型匹配目的地，比字符串拼接路由更安全（不会出现拼错路径的低级错误）。
  2. 把 $users[index]（Binding）传给详情页，编辑结果直接写回列表数据源——返回后列表自动显示新值，不需要额外的「刷新回调」。
  3. .sheet 默认可下滑关闭，表单场景要注意未保存就关闭的问题（必要时加 .interactiveDismissDisabled()）；关闭用 @Environment(\.dismiss) 调用。

常见错误：

  1. 用 NavigationView → iOS 16+ 已 deprecated，新代码一律 NavigationStack。
  2. 详情页接收 let user: Person（值拷贝）后修改 → 改的是副本，返回后列表不变（本题考查 Binding 的原因）。
  3. 想用字符串路由 NavigationLink("detail/\(id)") → 那是安卓/前端的思路，SwiftUI 用 value + navigationDestination。

题目 9 · 登录表单与校验（对应概念 12） ​

难度：进阶

题目：实现登录表单：邮箱输入框、密码框（遮罩）、登录按钮；点击登录时校验邮箱必须含 @、密码至少 6 位，错误信息显示在对应输入框下方，输入时清除错误。

要求：

  • 用 Form 容器 + TextField / SecureField
  • 邮箱框设置 .keyboardType(.emailAddress)、.textInputAutocapitalization(.never)、.submitLabel(.next)
  • 校验通过才打印提交信息

提示：前端锚点——$email 双向绑定 ≈ v-model；keyboardType / submitLabel 是移动端独有的键盘控制（前端没有对应概念）。

参考答案
swift
import SwiftUI

struct LoginForm: View {
    @State private var email = ""
    @State private var password = ""
    @State private var emailError: String?      // 用 String? 表达「没有错误」
    @State private var passwordError: String?

    var body: some View {
        Form {
            Section {
                TextField("邮箱", text: $email)
                    .keyboardType(.emailAddress)              // 弹出邮箱键盘
                    .textInputAutocapitalization(.never)      // 关闭首字母大写
                    .autocorrectionDisabled()                 // 关闭自动纠错
                    .submitLabel(.next)                       // 回车键显示「下一步」
                    .onChange(of: email) { _ in emailError = nil }   // 输入即清错

                if let emailError {
                    Text(emailError).foregroundColor(.red).font(.caption)
                }

                SecureField("密码", text: $password)   // 密码框，自带遮罩
                    .submitLabel(.done)
                    .onChange(of: password) { _ in passwordError = nil }

                if let passwordError {
                    Text(passwordError).foregroundColor(.red).font(.caption)
                }
            }

            Section {
                Button("登录") { submitForm() }
                    .frame(maxWidth: .infinity, alignment: .center)
            }
        }
    }

    private func submitForm() {
        // 提交时统一校验（而不是每次输入都校验，体验更好）
        emailError = email.contains("@") ? nil : "邮箱格式不正确"
        passwordError = password.count >= 6 ? nil : "密码至少 6 位"

        if emailError == nil && passwordError == nil {
            print("提交：\(email)，密码 \(password.count) 位")
        }
    }
}

要点解析：

  1. $email 是 @State 的双向绑定投影，比 React 受控组件少写 onChange；需要「输入时清除错误」这类副作用时用 .onChange(of:) 补上。
  2. Form 会自动应用系统样式（分组、圆角、分隔线），和直接用 VStack 布局差异很大——二者按场景选，不要混着理解。
  3. submitLabel 只改变回车键显示文案，不会自动提交或跳转焦点，需要配合 .onSubmit { } 处理。

常见错误：

  1. TextField("邮箱", text: email) 忘 $ → 编译报错。
  2. 传 @Binding 给子视图时忘记 $ → 同样编译报错（这是 SwiftUI 新手最常遇到的报错之一）。
  3. 期望 submitLabel(.next) 自动聚焦下一个输入框 → 它只改文案，焦点要自己用 @FocusState 管理。

题目 10 · 综合：可增删的待办列表（对应概念 06-12） ​

难度：综合

题目：实现一个完整待办页：顶部输入框 + 添加按钮，中间 List 展示待办（每行带完成开关），支持左滑删除，底部显示「共 N 条 · 已完成 M 条」，列表为空时显示空状态提示。

要求：

  • 数据模型 Todo: Identifiable（id、title、isDone）
  • 所有状态集中在页面视图，TodoRow 用 @Binding 接收单项（无自有状态）
  • 完成数从列表派生（count { $0.isDone }），不额外存状态
  • 空列表时显示「还没有待办，添加一条吧」

提示：前端锚点——这就是 React 经典 Todo 练习：状态提升 + 受控输入 + map 列表 + 不可变更新，SwiftUI 版本靠 @Binding 直接回写。

参考答案
swift
import SwiftUI

struct Todo: Identifiable {
    let id: Int
    var title: String
    var isDone: Bool = false
}

struct TodoApp: View {
    @State private var todos: [Todo] = []
    @State private var input = ""
    @State private var nextId = 1

    // 派生数据：从 todos 算出来，绝不存第二份状态
    private var doneCount: Int { todos.filter { $0.isDone }.count }

    var body: some View {
        VStack(spacing: 0) {
            // ---------- 输入区 ----------
            HStack {
                TextField("想做点什么", text: $input)
                    .textFieldStyle(.roundedBorder)
                Button("添加") { addTodo() }
                    .buttonStyle(.borderedProminent)
            }
            .padding()

            Divider()

            // ---------- 列表区 ----------
            if todos.isEmpty {
                // 空状态：别让页面白屏
                VStack(spacing: 8) {
                    Spacer()
                    Text("还没有待办，添加一条吧")
                        .foregroundColor(.gray)
                    Spacer()
                }
            } else {
                List {
                    // $todos 生成对数组元素的 Binding，子视图改动直接写回数组
                    ForEach($todos) { $todo in
                        TodoRow(todo: $todo)
                    }
                    .onDelete { indexSet in
                        todos.remove(atOffsets: indexSet)
                    }
                }
                .listStyle(.plain)
            }

            // ---------- 底部统计 ----------
            Divider()
            Text("共 \(todos.count) 条 · 已完成 \(doneCount) 条")
                .font(.subheadline)
                .foregroundColor(.gray)
                .padding(.vertical, 8)
        }
    }

    private func addTodo() {
        let title = input.trimmingCharacters(in: .whitespaces)
        guard !title.isEmpty else { return }
        todos.append(Todo(id: nextId, title: title))
        nextId += 1
        input = ""
    }
}

// 无状态子视图：通过 @Binding 读写父级的某一项
struct TodoRow: View {
    @Binding var todo: Todo

    var body: some View {
        HStack(spacing: 12) {
            // Toggle 绑定 Bool 的 Binding
            Toggle("", isOn: $todo.isDone)
                .labelsHidden()
                .toggleStyle(.switch)
            Text(todo.title)
                .strikethrough(todo.isDone)          // 完成时加删除线
                .foregroundColor(todo.isDone ? .gray : .primary)
            Spacer()
        }
        .padding(.vertical, 4)
    }
}

要点解析：

  1. ForEach($todos) { $todo in ... } 是 SwiftUI 的精髓：直接拿到数组元素的 Binding，子视图的改动（勾选）原地写回数组，不需要回调层层上报。
  2. doneCount 用计算属性派生，而不是在勾选时手动 +1/-1——派生数据存两份必然不同步，这是状态管理的通用原则。
  3. 空状态是移动端的基本素养：空白页面会让用户分不清「加载中」和「真的没有数据」。

常见错误：

  1. 把 doneCount 声明成 @State 并在 Toggle 里手动加减 → 两份状态容易不同步，且漏处理删除场景。
  2. 子视图用 let todo: Todo 接收却要改 isDone → 值类型拷贝，改不到父级数据。
  3. 用 ForEach(todos.indices, id: \.self) 配合删除 → 下标 id 在删除后会错位（应让模型遵循 Identifiable）。
