题目 1 · 计数器：@State 驱动视图（对应概念 06） ​

难度：基础

题目：实现一个计数器：屏幕中间显示当前数字（较大字号），下方「+1」按钮加一、「重置」按钮归零。

要求：

  • 状态用 @State count: number = 0（显式类型标注，ArkTS 严格模式要求）
  • build() 有且仅有一个根容器，且根节点是容器组件
  • 不要出现任何「手动改视图」的代码（ArkUI 声明式场景不用 findComponentById 改属性）

提示：前端锚点——@State ≈ useState，改状态 → build() 重新执行 → 视图自动更新；build() 就是 Vue 的 template + render。

参考答案
typescript
@Entry
@Component
struct Counter {
  @State count: number = 0   // 可观察状态：变化触发 build() 重新执行

  build() {
    Column({ space: 16 }) {                 // 根容器（build 的根节点只能是容器组件）
      Text(`当前计数：${this.count}`)
        .fontSize(40)
        .fontWeight(FontWeight.Bold)

      Row({ space: 12 }) {
        Button('+1')
          .onClick(() => {
            this.count += 1                 // 改状态 -> build() 自动重执行
          })
        Button('重置')
          .onClick(() => {
            this.count = 0
          })
      }
    }
    .width('100%')
    .height('100%')
    .justifyContent(FlexAlign.Center)       // 主轴居中
    .alignItems(ItemAlign.Center)           // 交叉轴居中
  }
}

要点解析：

  1. @State 让成员变量可观察：状态一变，ArkUI 重新执行 build()，不需要手动刷新视图。
  2. @State 有严格类型要求：@State count = 0 会被推导为 number，赋字符串编译报错——显式写 : number 是好习惯。
  3. build() 里必须用 this.count 访问状态（ArkUI 的 struct 写法类似 Vue SFC 的 this.xxx）。

常见错误：

  1. 用普通成员变量 count: number = 0 后自增 → 值变了但 UI 不动（框架不知道要刷新）。
  2. build() 里并列写 Text() 和 Button() 不套容器 → 编译报错，根节点必须是容器组件。
  3. 在 build() 里做副作用（发请求、写文件）→ 每次刷新都执行，重复触发。

题目 2 · 待办最小原型（对应概念 06） ​

难度：进阶

题目：用声明式思维实现「待办添加 + 列表显示」：一个输入框、一个「添加」按钮，下方逐行显示已添加的待办。

要求：

  • 先列状态（输入文本、待办数组），再写 UI，最后加事件
  • TextInput 必须在 onChange 里手动赋值 @State（ArkUI 没有自动双向绑定）
  • 输入为空（含纯空格）时不产生空条目，添加成功后清空输入框
  • 更新数组用不可变方式（this.todos = [...this.todos, text]）

提示：前端锚点——这是 Vue SFC 的结构感 + React 的不可变更新；注意 ArkUI 的 TextInput 不像 v-model，必须自己写 onChange 赋值。

参考答案
typescript
@Entry
@Component
struct TodoMini {
  @State input: string = ''           // 输入框内容
  @State todos: string[] = []         // 待办列表

  build() {
    Column({ space: 12 }) {
      Row({ space: 8 }) {
        TextInput({ placeholder: '想做点什么' })
          .layoutWeight(1)            // 占满剩余宽度（类比 flex: 1）
          .onChange((value: string) => {
            this.input = value        // 手动赋值：ArkUI 没有自动双向绑定
          })
        Button('添加')
          .onClick(() => {
            const text: string = this.input.trim()
            if (text.length === 0) {
              return                  // 挡住空输入和纯空格
            }
            this.todos = [...this.todos, text]   // 不可变更新：生成新数组
            this.input = ''           // 清空输入框
          })
      }
      .width('100%')

      // 状态映射成视图：数组有几条就渲染几个 Text
      Column({ space: 6 }) {
        ForEach(this.todos, (todo: string) => {
          Text(`• ${todo}`)
            .width('100%')
        }, (todo: string) => todo)    // keyGenerator：类比 React 的 key
      }
      .width('100%')
    }
    .padding(16)
    .width('100%')
    .height('100%')
    .alignItems(ItemAlign.Start)
  }
}

要点解析：

  1. TextInput 的 value 是初始值，用户输入不会自动写回状态，必须在 onChange 里手动赋值——这是 ArkUI 与 Vue v-model 最大的手感差异。
  2. 列表更新用 [...this.todos, text] 生成新数组：原地 push 不会被框架感知，UI 不刷新。
  3. ForEach 的第三个参数是 keyGenerator（类比 React 的 key），增删场景建议指定——本例用内容当 key 仅作演示，真实场景用 id。

常见错误：

  1. 只写 TextInput({ placeholder: 'x' }) 不写 onChange → 拿不到用户输入。
  2. this.todos.push(text) → 数组变了但 UI 不刷新（不可变更新的经典坑）。
  3. 忘记 trim() → 输入空格也能添加空条目。

题目 3 · 三段式布局（对应概念 07） ​

难度：基础

题目：实现「顶部标题 + 中间内容 + 底部按钮」的三段式布局：标题在最上，按钮吸底，中间内容吃掉所有剩余空间并居中。

要求：

  • 用 Column + Blank() 撑开中间区域
  • 按钮宽度占满（.width('100%')）
  • 整屏内边距 16vp，标题左对齐

提示：前端锚点——ArkUI 的布局 API 是三端里最像 CSS 的：justifyContent(FlexAlign.Start/Center/SpaceBetween) 与 justify-content 完全对应。

参考答案
typescript
@Entry
@Component
struct ThreeSectionLayout {
  build() {
    Column() {
      Text('页面标题')
        .fontSize(24)
        .fontWeight(FontWeight.Bold)
        .width('100%')
        .textAlign(TextAlign.Start)     // 标题左对齐

      Blank()                            // 弹性空白：吃掉剩余空间（类比 flex-grow: 1）

      Text('中间内容区域')
        .fontColor(Color.Gray)

      Blank()                            // 两个 Blank 平分剩余空间 -> 内容居中

      Button('提交')
        .width('100%')                   // 类比 width: 100%
        .onClick(() => {
          console.info('提交')
        })
    }
    .padding(16)
    .width('100%')
    .height('100%')
    .alignItems(ItemAlign.Start)         // 交叉轴对齐（类比 align-items）
  }
}

要点解析：

  1. justifyContent 对应 justify-content（主轴），alignItems 对应 align-items（交叉轴），Column({ space: 16 }) 的 space 对应 gap——这是三端里最贴近 CSS 的一套。
  2. Blank() 是弹性空白组件（类比 flex-grow: 1 的空元素）；要固定间距用 .height(24) 或容器的 space。
  3. 注意 Column 的 space 只作用于直接子元素，嵌套容器之间的间距要单独设置。

常见错误：

  1. 忘了外层 .height('100%') → 容器高度只包裹内容，Blank() 没有可撑开的空间，按钮不会吸底。
  2. 想用数字控制层级（如 zIndex(999)）→ 移动端层叠顺序 = 代码书写顺序（后写的在上），要调层级就调顺序或用 Stack。
  3. .margin() 与 .padding() 顺序写反 → ArkUI 的链式调用顺序影响最终尺寸（margin 在外、padding 在内），不像 CSS 属性顺序无关。

题目 4 · 横向卡片与层叠（对应概念 07） ​

难度：进阶

题目：实现一个消息卡片：左侧 40vp 圆形头像占位，中间标题 + 副标题（占满剩余宽度、副标题单行省略），右侧灰色时间；头像右上角叠一个红色「未读」小红点。

要求：

  • 用 Row 横向排列，中间 Column 用 .layoutWeight(1)
  • 副标题 .maxLines(1) + .textOverflow({ overflow: TextOverflow.Ellipsis })
  • 红点用 Stack 层叠 + .alignRules 或 Badge/.position 叠加在头像右上角

提示：前端锚点——Row = flex-direction: row，layoutWeight(n) = flex: n，Stack = position: relative + 绝对定位子元素。

参考答案
typescript
@Entry
@Component
struct MessageCardDemo {
  build() {
    Column() {
      MessageCard({
        title: '系统通知',
        subtitle: '这是一条很长很长很长很长很长的消息预览内容',
        time: '10:24',
        unread: true
      })
    }
    .padding(16)
    .width('100%')
  }
}

@Component
struct MessageCard {
  title: string = ''
  subtitle: string = ''
  time: string = ''
  unread: boolean = false

  build() {
    Row({ space: 12 }) {
      // 层叠容器：头像 + 右上角红点（后写的在上层）
      Stack() {
        Text('头')
          .width(40)
          .height(40)
          .fontSize(16)
          .fontColor(Color.White)
          .textAlign(TextAlign.Center)
          .borderRadius(20)
          .backgroundColor(Color.Gray)

        if (this.unread) {
          Text('')
            .width(10)
            .height(10)
            .borderRadius(5)
            .backgroundColor(Color.Red)
            .margin({ left: 30, bottom: 30 })   // 往右上角偏移
        }
      }
      .width(40)
      .height(40)
      .alignContent(Alignment.TopStart)

      // 中间区域占满剩余宽度（layoutWeight = flex: 1）
      Column({ space: 2 }) {
        Text(this.title)
          .fontWeight(FontWeight.Medium)
          .maxLines(1)
          .textOverflow({ overflow: TextOverflow.Ellipsis })
        Text(this.subtitle)
          .fontSize(13)
          .fontColor(Color.Gray)
          .maxLines(1)
          .textOverflow({ overflow: TextOverflow.Ellipsis })
      }
      .layoutWeight(1)
      .alignItems(HorizontalAlign.Start)

      Text(this.time)
        .fontSize(12)
        .fontColor(Color.Gray)
    }
    .width('100%')
    .padding(16)
    .alignItems(VerticalAlign.Center)
  }
}

要点解析：

  1. layoutWeight(n) 等价于 flex: n，但只在父容器是 Row / Column / Flex 时生效。
  2. Stack 的 alignContent 控制子元素对齐，后写的子元素在上层；移动端没有 z-index 数字，改层级靠调整书写顺序。
  3. 文本省略要同时设置 maxLines(1) 和 textOverflow，缺一个都不生效。

常见错误：

  1. 中间 Column 忘了 layoutWeight(1) → 副标题过长会把右侧时间挤出屏幕。
  2. 在非 Row/Column/Flex 容器里用 layoutWeight → 不生效。
  3. .padding() 写在 .width('100%') 之后导致总宽超出屏幕 → 链式顺序敏感，尺寸类修饰通常先写。

题目 5 · 可复用卡片与 @Styles（对应概念 08） ​

难度：进阶

题目：封装一个 Card 组件：接收 title 和一个 @BuilderParam 内容插槽，负责标题样式、内边距与卡片外观；再用 @Styles 抽出可复用的样式。

要求：

  • 插槽用 @BuilderParam content: () => void
  • 所有成员变量必须有默认值（ArkTS 严格模式要求）
  • 调用时用尾随闭包形式 Card({ title: 'x' }) { ... }
  • 用 @Styles 定义一处可复用样式并说明它的限制

提示：前端锚点——@BuilderParam ≈ Vue 的 slot，@Builder ≈ 渲染函数/片段，@Styles ≈ CSS 样式类（但只能复用通用属性）。

参考答案
typescript
// 子组件：@Component struct，成员变量 = props
@Component
struct Card {
  title: string = ''                    // 必须给默认值，否则编译报错
  @BuilderParam content: () => void     // 插槽：接收一段 UI 内容

  build() {
    Column({ space: 8 }) {
      Text(this.title)
        .fontSize(18)
        .fontWeight(FontWeight.Bold)
        .width('100%')
        .textAlign(TextAlign.Start)
      this.content()                    // 在此处插入调用方传入的内容
    }
    .cardBox()                          // 复用 @Styles 定义的样式
  }
}

// 样式复用：@Styles（组件内定义，不加 function 关键字）
@Styles
function cardBox() {
  .padding(16)
  .width('100%')
  .backgroundColor('#F5F5F5')
  .borderRadius(8)
}

// 全局 @Builder：可复用的 UI 片段
@Builder
function Greeting(name: string) {
  Text(`你好，${name}`).fontSize(16)
}

@Entry
@Component
struct Screen {
  build() {
    Column({ space: 12 }) {
      // 尾随闭包形式传插槽内容（ArkUI 的插槽只能这样传）
      Card({ title: '基本信息' }) {
        Text('姓名：Claude')
        Text('年龄：30')
      }
      Card({ title: '联系方式' }) {
        Text('邮箱：claude@example.com')
      }
      Greeting('Claude')                // 复用 @Builder 片段
    }
    .padding(16)
    .width('100%')
  }
}

要点解析：

  1. @BuilderParam 只能在 @Component struct 内声明，且父组件传插槽必须用尾随闭包 Card({...}) { ... }，不能当普通参数传。
  2. @Styles 只能复用通用属性（尺寸、背景、边距等），不能传参；需要传参的样式用 @Extend(Text) 之类的扩展。
  3. 全局 @Builder 函数直接用（Greeting('x')），组件内 @Builder 方法用 this.xxx()；ArkUI 不支持泛型组件，通用列表要靠 @BuilderParam 传入渲染逻辑。

常见错误：

  1. 成员变量不写默认值（title: string）→ 编译报错。
  2. 试图像函数一样传插槽：Card({ title: 'x', content: () => {...} }) → 不符合 ArkUI 的插槽传法。
  3. 在 @Styles 里写 .fontSize(18) 这类组件专属属性 → @Styles 不支持（含字体等文本专属属性），要用 @Extend(Text)。

题目 6 · @Link 双向绑定与状态提升（对应概念 09） ​

难度：进阶

题目：把计数器拆成两层：父组件持有 @State count，子组件用 @Link count: number 接收（无自有状态）；页面上放两个子组件，共享同一个计数。

要求：

  • 父传子用 $count（$ 取引用传给 @Link）
  • 子组件不能给默认值（@Link 必须由父传入）
  • 两个子组件任一操作，数字都同步变化
  • 能说清 @Prop（单向拷贝）与 @Link（双向引用）的区别，并各举一个适用场景

提示：前端锚点——@Link ≈ Vue 的 v-model（双向），@Prop ≈ React 的 props（单向只读）；ArkUI 把两者做成了不同的装饰器。

参考答案
typescript
@Component
struct CounterView {
  @Link count: number      // 双向绑定：改它即改父级源（不能给默认值）
  step: number = 1         // 普通 props：必须有默认值

  build() {
    Row({ space: 12 }) {
      Text(`计数：${this.count}`).fontSize(20)
      Button(this.step > 0 ? '+1' : '-1')
        .onClick(() => {
          this.count += this.step     // 直接改 @Link，父级状态同步变化
        })
    }
  }
}

@Component
struct DisplayView {
  @Prop value: number      // 单向：父变同步给子，子改不影响父（值拷贝）

  build() {
    Text(`只读展示：${this.value}`).fontSize(16).fontColor(Color.Gray)
  }
}

@Entry
@Component
struct CounterScreen {
  @State count: number = 0     // 父组件持有状态（唯一真相源）

  build() {
    Column({ space: 20 }) {
      // $count 取引用传给 @Link；DisplayView 用 @Prop 单向展示
      CounterView({ count: $count, step: 1 })
      CounterView({ count: $count, step: -1 })
      DisplayView({ value: this.count })
    }
    .width('100%')
    .height('100%')
    .justifyContent(FlexAlign.Center)
    .alignItems(ItemAlign.Center)
  }
}

要点解析：

  1. @Prop 是值拷贝（父变同步给子，子改不影响父），@Link 是引用双向（改子即改父）——需要回传用 @Link，纯展示用 @Prop，别用混。
  2. @Link 成员不能给默认值（必须由父传入），@Prop 必须给默认值（ArkTS 初始化要求）。
  3. 跨层共享可用 @Provide / @Consume（按属性名匹配），全局可用 AppStorage + @StorageLink；但不要过早用全局 store，会难以追踪数据流。

常见错误：

  1. 子组件也写 @State count → 父子两份独立状态，点了不同步（L2 最典型的状态 bug）。
  2. 给 @Link 成员写默认值 → 编译报错。
  3. 传值时忘了 $ → 报类型不匹配（需要引用却给了值）。

题目 7 · 列表渲染与懒加载（对应概念 10） ​

难度：进阶

题目：用 List 渲染 100 条用户数据（头像占位 + 姓名 + 年龄），并支持点击右侧删除按钮移除该项。

要求：

  • List({ space: 8 }) + ForEach，keyGenerator 用 item.id.toString()（必须返回字符串）
  • 删除时生成新数组（不可变更新）
  • 说明 ForEach 与 LazyForEach 的区别，并给出 LazyForEach + IDataSource 的最小写法

提示：前端锚点——List + ForEach ≈ map 渲染，LazyForEach ≈ 虚拟滚动（但需要手写数据源，比前端繁琐）。

参考答案
typescript
interface User {
  id: number;
  name: string;
  age: number;
}

@Entry
@Component
struct UserListScreen {
  @State users: User[] = Array.from({ length: 100 },
    (_: number, i: number): User => ({ id: i + 1, name: `用户${i + 1}`, age: 18 + i % 30 }))

  build() {
    List({ space: 8 }) {
      ForEach(this.users, (user: User) => {
        ListItem() {
          Row({ space: 12 }) {
            Text('头')
              .width(40)
              .height(40)
              .borderRadius(20)
              .textAlign(TextAlign.Center)
              .backgroundColor(Color.Gray)
            Column({ space: 2 }) {
              Text(user.name)
              Text(`${user.age} 岁`).fontSize(12).fontColor(Color.Gray)
            }
            .layoutWeight(1)
            .alignItems(HorizontalAlign.Start)
            Button('删除')
              .onClick(() => {
                // 不可变更新：过滤掉目标项，生成新数组
                this.users = this.users.filter((u: User) => u.id !== user.id)
              })
          }
          .padding(16)
          .width('100%')
        }
      }, (user: User) => user.id.toString())   // keyGenerator：必须返回字符串
    }
    .padding({ top: 8, bottom: 8 })
  }
}

进阶：LazyForEach + IDataSource（数据量大时用）

typescript
class UserDataSource implements IDataSource {
  private users: User[] = [];

  totalCount(): number {
    return this.users.length;
  }

  getData(index: number): User {
    return this.users[index];
  }

  // 注册/注销数据监听器（数据变化时通过 listener 通知刷新）
  registerDataChangeListener(listener: DataChangeListener): void {}
  unregisterDataChangeListener(listener: DataChangeListener): void {}

  setData(users: User[]): void {
    this.users = users;
  }
}

// 用法：
//   private data: UserDataSource = new UserDataSource()
//   List({ space: 8 }) {
//     LazyForEach(this.data, (item: User) => {
//       ListItem() { Text(item.name) }
//     }, (item: User) => item.id.toString())
//   }

要点解析：

  1. ForEach 不懒加载（一次性渲染全部），数据量小用它；LazyForEach 按需渲染，但必须配合 IDataSource（实现 totalCount / getData / 监听器注册），是三端中最繁琐的。
  2. keyGenerator（第三个参数）类比 React 的 key，必须返回字符串——直接返回 number 会报错。
  3. 用 LazyForEach 时，直接改数组不会刷新，必须通过 DataChangeListener 的 onDataChange / onDataAdd / onDataDelete 通知。

常见错误：

  1. keyGenerator 返回 item.id（number）→ 类型不符，必须 .toString()。
  2. 1000 条数据用 ForEach → 一次性全部创建，卡顿；应换 LazyForEach。
  3. 用 LazyForEach 却直接 this.users = newArr 期待刷新 → 要走 listener 通知。

题目 8 · 列表页跳详情页（对应概念 11） ​

难度：进阶

题目：用 Navigation + NavPathStack 实现「用户列表 → 用户详情 → 返回」：首页列出 3 个用户，点击某用户进入详情并显示其 ID，详情页有返回按钮。

要求：

  • 用 Navigation(this.pathStack) 容器 + .navDestination(this.PageMap) 绑定路由表
  • PageMap 用 @Builder 声明，按 name 条件返回页面
  • 跳转 pushPath({ name: 'detail' })，返回 pop()
  • 参数通过组件属性传递（父组件 @State 记录当前选中 ID）

提示：前端锚点——NavPathStack ≈ 浏览器 history 的栈模型，pushPath ≈ navigate()，pop() ≈ 后退；PageMap ≈ <Routes> 的路由表。

参考答案
typescript
interface User {
  id: number;
  name: string;
}

@Entry
@Component
struct MainPage {
  @State currentUserId: number = 0                 // 记录当前查看的用户
  private pathStack: NavPathStack = new NavPathStack()

  build() {
    Navigation(this.pathStack) {
      Column({ space: 12 }) {
        Text('用户列表').fontSize(22)
        ForEach([
          { id: 1, name: 'Alice' } as User,
          { id: 2, name: 'Bob' } as User,
          { id: 3, name: 'Charlie' } as User
        ], (user: User) => {
          Button(`${user.name}（ID: ${user.id}）`)
            .onClick(() => {
              this.currentUserId = user.id          // 先记录参数
              this.pathStack.pushPath({ name: 'detail' })   // 再压栈跳转
            })
        }, (user: User) => user.id.toString())
      }
      .padding(16)
      .alignItems(HorizontalAlign.Start)
    }
    .navDestination(this.PageMap)                  // 绑定路由表
  }

  // 路由表：根据 name 返回对应页面（@Builder 声明）
  @Builder
  PageMap(name: string) {
    if (name === 'detail') {
      DetailPage({ userId: this.currentUserId, pathStack: this.pathStack })
    }
  }
}

@Component
struct DetailPage {
  userId: number = 0
  pathStack: NavPathStack = new NavPathStack()    // 由父组件传入同一个栈实例

  build() {
    Column({ space: 16 }) {
      Text('用户详情页').fontSize(22)
      Text(`用户 ID: ${this.userId}`)
      Button('返回')
        .onClick(() => {
          this.pathStack.pop()                     // 弹栈返回
        })
    }
    .width('100%')
    .height('100%')
    .justifyContent(FlexAlign.Center)
  }
}

要点解析：

  1. Navigation + NavPathStack 是栈模型（新版推荐），旧版 Router 基于页面 URL；两者并存，看文档和示例时要注意区分。
  2. 官方也支持 pushPath({ name, param }) + getParamByName('detail') 取参，或 PageMap(name, param) 接收参数；本例用「父组件 @State 记录 + 属性传递」更确定，也更符合单向数据流。
  3. @Builder PageMap 的路由表是字符串条件判断，没有编译期检查——路由名建议抽成常量管理。

常见错误：

  1. pushPath 连续快速调用 → 它是异步的，连续跳转可能导致栈错乱（加防抖或禁用按钮）。
  2. PageMap 里忘了 if (name === ...) 的分支 → 跳转后白屏。
  3. 详情页自己 new NavPathStack() 而不接收父级栈 → pop() 弹的是另一个空栈，返回无效。

题目 9 · 登录表单与校验（对应概念 12） ​

难度：进阶

题目：实现登录表单：邮箱输入框、密码框（遮罩）、登录按钮；点击登录时校验——邮箱必须含 @、密码至少 6 位，错误信息显示在对应输入框下方，输入时清除错误。

要求：

  • 用 TextInput，.type(InputType.Email) / .type(InputType.Password) 指定键盘类型
  • onChange 里手动赋值 @State 并清除错误
  • 错误提示用条件渲染 if (this.emailError)，错误时输入框边框变红
  • 校验通过才打印提交信息

提示：前端锚点——$state 自动绑定在 ArkUI 里不存在，TextInput 必须手写 onChange 赋值；InputType 相当于移动端的 inputmode。

参考答案
typescript
@Entry
@Component
struct LoginForm {
  @State email: string = ''
  @State password: string = ''
  @State emailError: string = ''
  @State passwordError: string = ''

  build() {
    Column({ space: 12 }) {
      TextInput({ placeholder: '邮箱' })
        .type(InputType.Email)                    // 弹出邮箱键盘
        .onChange((value: string) => {
          this.email = value                      // 手动赋值：ArkUI 没有自动双向绑定
          this.emailError = ''                    // 输入即清错
        })
        .border({
          width: 1,
          color: this.emailError ? Color.Red : Color.Gray   // 条件样式：错误时红框
        })

      if (this.emailError) {                      // 条件渲染错误提示
        Text(this.emailError).fontSize(12).fontColor(Color.Red).width('100%')
      }

      TextInput({ placeholder: '密码' })
        .type(InputType.Password)                 // 密码类型（自带遮罩）
        .onChange((value: string) => {
          this.password = value
          this.passwordError = ''
        })
        .border({
          width: 1,
          color: this.passwordError ? Color.Red : Color.Gray
        })

      if (this.passwordError) {
        Text(this.passwordError).fontSize(12).fontColor(Color.Red).width('100%')
      }

      Button('登录')
        .width('100%')
        .onClick(() => {
          this.submitForm()
        })
    }
    .padding(16)
    .width('100%')
    .height('100%')
  }

  private submitForm(): void {
    // 提交时统一校验（而不是每次输入都校验，体验更好）
    this.emailError = this.email.includes('@') ? '' : '邮箱格式不正确'
    this.passwordError = this.password.length >= 6 ? '' : '密码至少 6 位'

    if (!this.emailError && !this.passwordError) {
      console.info(`提交：${this.email}`)
    }
  }
}

要点解析：

  1. ArkUI 的 TextInput 没有内置错误态属性，错误样式要自己用条件颜色/边框实现（不像前端表单库有现成的 error 字段）。
  2. onChange 里必须手动给 @State 赋值，同时顺手清掉错误提示——这是 ArkUI 表单的标准写法。
  3. InputType 控制键盘类型（移动端独有）；enterKeyType 控制回车键文案，与前端的 inputmode / enterkeyhint 概念接近。

常见错误：

  1. 只写 TextInput({ placeholder: 'x' }) 忘了 onChange → 状态永远是空，校验必然失败。
  2. 把 value 当「受控值」用（设置 value 后用户输入可能被覆盖）→ ArkUI 的 value 更多是初始值，持续同步靠 onChange。
  3. 每次输入都校验 → 用户刚打第一个字符就看到红字，体验差（应提交时或失焦时校验）。

题目 10 · 综合：可增删的待办列表（对应概念 06-12） ​

难度：综合

题目：实现一个完整待办页：顶部输入框 + 添加按钮，中间 List 展示待办（每行带完成开关），支持点击删除，底部显示「共 N 条 · 已完成 M 条」，列表为空时显示空状态提示。

要求：

  • 模型 interface Todo { id: number; title: string; done: boolean }
  • 所有状态集中在页面组件，TodoRow 用 @Link 接收单项（无自有状态）
  • 完成数从列表派生（getter 或方法计算），不额外存状态
  • 删除与勾选都用不可变更新（生成新数组）
  • 空列表时显示「还没有待办，添加一条吧」

提示：前端锚点——@Link 让子组件直接改父级数据，比 React 的「回调层层上报」少写很多代码；不可变更新仍是必须的。

参考答案
typescript
interface Todo {
  id: number;
  title: string;
  done: boolean;
}

@Component
struct TodoRow {
  @Link todo: Todo          // 双向绑定：改动直接写回父级数组

  build() {
    Row({ space: 12 }) {
      Toggle({ type: ToggleType.Checkbox, isOn: this.todo.done })
        .onChange((isOn: boolean) => {
          this.todo.done = isOn     // 改 @Link 即改父级数据
        })
      Text(this.todo.title)
        .layoutWeight(1)
        .decoration({
          type: this.todo.done ? TextDecorationType.LineThrough : TextDecorationType.None
        })
        .fontColor(this.todo.done ? Color.Gray : Color.Black)
      Button('删除')
        .fontSize(12)
        .onClick(() => {
          // 删除动作通过回调交给父组件（集合的增删应该在持有者手里）
          this.onDelete()
        })
    }
    .padding(12)
    .width('100%')
  }

  // 通过回调让父组件删除自己（ArkUI 的 @Link 适合改内容，不适合改集合）
  onDelete: () => void = () => {}
}

@Entry
@Component
struct TodoApp {
  @State todos: Todo[] = []
  @State input: string = ''
  @State nextId: number = 1

  // 派生数据：从 todos 算出来，绝不存第二份状态
  private get doneCount(): number {
    return this.todos.filter((t: Todo) => t.done).length
  }

  build() {
    Column() {
      // ---------- 输入区 ----------
      Row({ space: 8 }) {
        TextInput({ placeholder: '想做点什么' })
          .layoutWeight(1)
          .onChange((value: string) => { this.input = value })
        Button('添加')
          .onClick(() => {
            const title: string = this.input.trim()
            if (title.length === 0) {
              return
            }
            this.todos = [...this.todos, { id: this.nextId, title: title, done: false }]
            this.nextId += 1
            this.input = ''
          })
      }
      .padding(16)
      .width('100%')

      Divider()

      // ---------- 列表区 ----------
      if (this.todos.length === 0) {
        // 空状态：别让页面白屏
        Column() {
          Blank()
          Text('还没有待办，添加一条吧').fontColor(Color.Gray)
          Blank()
        }
        .layoutWeight(1)
        .width('100%')
      } else {
        List({ space: 8 }) {
          ForEach(this.todos, (todo: Todo) => {
            ListItem() {
              // $todo 取引用传给 @Link，子组件的改动写回本数组元素
              TodoRow({ todo: $todo, onDelete: () => {
                this.todos = this.todos.filter((t: Todo) => t.id !== todo.id)
              } })
            }
          }, (todo: Todo) => todo.id.toString())
        }
        .layoutWeight(1)
        .width('100%')
      }

      Divider()

      // ---------- 底部统计 ----------
      Text(`共 ${this.todos.length} 条 · 已完成 ${this.doneCount} 条`)
        .fontSize(13)
        .fontColor(Color.Gray)
        .padding(8)
    }
    .width('100%')
    .height('100%')
  }
}

要点解析：

  1. ForEach(this.todos, ...) 中用 $todo 取引用传给 @Link，子组件的勾选原地写回数组元素——不需要写回调层层上报。
  2. 集合的增删仍要父组件做（生成新数组），@Link 适合改「已有元素的内容」，不适合改集合结构。
  3. doneCount 用 getter 派生，而不是在勾选时手动 +1/-1——派生数据存两份必然不同步。

常见错误：

  1. 把 doneCount 声明成 @State 并手动维护 → 删除已完成项时会算错，两份状态必然漂移。
  2. 子组件用 @Prop todo: Todo 却要改 done → @Prop 是值拷贝，改不到父级。
  3. 删除用 this.todos.splice(index, 1) → 原地修改不触发刷新，必须赋新数组。
