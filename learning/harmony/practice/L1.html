鸿蒙 L1 习题集 ​

覆盖概念：01 Hello World 与项目结构 · 02 语法基础 · 03 集合与数据结构 · 04 异步编程 · 05 错误处理与空安全 对应等级：L1 新手入门（能力目标见 levels.md） 使用方式：先自己写完，再对答案。用 /practice harmony L1 可让 AI 陪练抽取题目并做代码评审。

题目 1 · 跑通第一个程序并拆出组件（对应概念 01） ​

难度：基础

题目：用 DevEco Studio 创建一个 Empty Ability 项目，把屏幕文字改成「你好，鸿蒙」，并抽成一个独立的 @Component struct Greeting（接收 name 属性），在入口组件里使用两次（传入不同名字）。再加一个按钮，点击后在控制台输出一行日志。

要求：

  • 入口保留 @Entry @Component struct Index + build()
  • build() 里只能有一个根容器，且根节点必须是容器组件（Column / Row / Stack）
  • Greeting 的成员变量必须有默认值（ArkTS 严格模式要求）
  • 能说清 Index.ets 的职责

提示：前端锚点——@Entry ≈ main.jsx 的入口标记，@Component struct + build() ≈ Vue 的 SFC，链式调用 .onClick() ≈ Vue 的指令。

参考答案
typescript
// entry/src/main/ets/pages/Index.ets

// 子组件：@Component 装饰 struct，成员变量 = props
@Component
struct Greeting {
  name: string = ''   // ArkTS 严格模式：成员变量必须初始化（给默认值）

  build() {
    Text(`你好，${this.name}`)
      .fontSize(20)
  }
}

@Entry                // 页面入口标记
@Component            // 声明为组件
struct Index {
  build() {
    // build() 必须有且仅有一个根容器，且根节点只能是容器组件
    Column({ space: 12 }) {
      Greeting({ name: '鸿蒙' })
      Greeting({ name: 'ArkTS' })
      Button('打个招呼')
        .onClick(() => {
          console.info('按钮被点击了')   // 输出到 HiLog
        })
    }
    .padding(16)
  }
}

要点解析：

  1. Index.ets 的职责是「作为页面入口（@Entry），在 build() 里描述页面视图树」。
  2. @Entry @Component struct + build() 是鸿蒙的固定写法，缺一不可；build() 里并列写两个 Text 会报错，必须套一个容器。
  3. 成员变量（props）必须给默认值，否则编译报错——这是 ArkTS 严格模式与 TS 的显著差异。

常见错误：

  1. build() 里直接写两个并列组件 → 编译报错「build 方法必须有且仅有一个根节点」。
  2. name: string 不给默认值 → ArkTS 要求属性初始化，编译报错。
  3. 把子组件也加上 @Entry → 一个页面只能有一个 @Entry，多标会导致页面注册冲突。

题目 2 · 接口、函数与模板字符串（对应概念 02） ​

难度：基础

题目：定义 interface User（含 name: string、age: number），写 formatUser(user: User): string 返回 "姓名(年龄)"，再写 adultNames(users: User[]): string[] 返回所有成年用户的名字。

要求：

  • 数据结构用 interface + 对象字面量（不要用 class）
  • 用模板字符串 `${x}` 拼接，不要用 +
  • 创建 3 个实例（含 1 个未成年），打印结果
  • 全程不出现 any，所有函数参数和返回值都显式标注类型

提示：前端锚点——ArkTS 语法基本就是 TypeScript，const/let、箭头函数、模板字符串、解构完全一致；差异是更严格：禁用 any、禁止动态加属性。

参考答案
typescript
// 用 interface + 字面量定义数据结构（ArkTS 推荐写法）
interface User {
  name: string;
  age: number;
}

// 参数与返回值都要显式类型注解（ArkTS 禁用 any，推导不出来就必须标注）
function formatUser(user: User): string {
  return `${user.name}(${user.age})`;
}

const adultNames = (users: User[]): string[] => {
  return users
    .filter((u: User) => u.age >= 18)
    .map((u: User) => u.name);
};

const users: User[] = [
  { name: 'Alice', age: 30 },
  { name: 'Bob', age: 17 },
  { name: 'Charlie', age: 25 }
];

for (const user of users) {          // 推荐用 for-of 直接拿元素
  console.info(formatUser(user));
}
// Alice(30)
// Bob(17)
// Charlie(25)

console.info(JSON.stringify(adultNames(users)));   // ["Alice","Charlie"]

// 解构（与 JS 完全一致）
const { name, age } = users[0];
console.info(`${name} 今年 ${age} 岁`);

要点解析：

  1. ArkTS 对前端最友好——const/let、箭头函数、模板字符串、解构与 JS 完全一致，迁移成本接近零。
  2. 比 TS 更严格的三点：禁用 any、禁用 undefined 缺省、禁止 obj.newField = 1 动态加属性（必须先在 interface 里声明）。
  3. 循环优先用 for...of；for...in 在 ArkTS 中被明确禁止（写了直接编译报错），要遍历对象用 Object.keys() + for...of。

常见错误：

  1. const user: User = { name: 'x', age: 1 }; user.city = '上海' → 编译报错，interface 里没有 city 就不能加。
  2. 函数参数漏写类型注解（(u) => u.name）→ ArkTS 推导不出来时必须显式标注 (u: User)。
  3. 用 for...in 遍历对象 → ArkTS 禁用该语法，编译报错。

题目 3 · 条件与循环（对应概念 02） ​

难度：基础

题目：写 function grade(score: number): string：0-59「不及格」、60-79「及格」、80-89「良好」、90-100「优秀」，超出范围抛出 ValidationError。

要求：

  • 用 if-else if-else 或三元表达式实现（ArkTS 有标准的三元运算符）
  • 自定义错误类 ValidationError extends Error
  • 写 5 个用例验证：45 / 60 / 85 / 100 / 101（最后一个要能捕获错误）
  • 另外用 switch 实现一遍，并说明为什么每个 case 都要写 break

提示：前端锚点——与 TS 完全一致；唯一要留意的两点：ArkTS 不支持 for...in，switch 的 break 漏写会「贯穿」（JS 的老坑被继承了）。

参考答案
typescript
// 自定义错误类（继承 Error，设置 name 便于区分错误类型）
class ValidationError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'ValidationError';
  }
}

// 写法一：if-else（最直观）
function grade(score: number): string {
  if (score < 0 || score > 100) {
    throw new ValidationError(`分数必须在 0-100 之间，收到 ${score}`);
  }
  if (score < 60) return '不及格';
  if (score < 80) return '及格';
  if (score < 90) return '良好';
  return '优秀';
}

// 写法二：switch（注意每个 case 都要 break，否则会贯穿执行下一个分支）
function gradeBySwitch(score: number): string {
  if (score < 0 || score > 100) {
    throw new ValidationError(`分数超出范围：${score}`);
  }
  const level: number = Math.floor(score / 10);
  switch (level) {
    case 10:
    case 9:
      return '优秀';    // return 会直接结束函数，不需要 break
    case 8:
      return '良好';
    case 7:
    case 6:
      return '及格';
    default:
      return '不及格';
  }
}

for (const score of [45, 60, 85, 100, 101]) {
  try {
    console.info(`${score} -> ${grade(score)}`);
  } catch (err) {
    // ArkTS 中 catch 的 err 是 unknown，需要类型断言才能访问 .message
    console.error(`${score} -> 错误：${(err as Error).message}`);
  }
}
// 45 -> 不及格
// 60 -> 及格
// 85 -> 良好
// 100 -> 优秀
// 101 -> 错误：分数必须在 0-100 之间，收到 101

要点解析：

  1. switch 的 case 漏写 break 会贯穿到下一个分支（JS 的经典老坑，ArkTS 继承了）；不过用 return 结尾的分支不会有问题（函数已返回）。
  2. catch (err) 中的 err 是 unknown 类型，必须类型断言（err as Error）才能访问 .message——这是 ArkTS 与 TS 严格模式一致的规则。
  3. 循环用 for...of 拿元素，for (let i = 0; i < n; i++) 拿下标，二者按需要选择；没有 for...in。

常见错误：

  1. switch 里每个 case 都忘写 break 且用赋值而非 return → 结果被后面的分支覆盖。
  2. catch (err) { console.error(err.message) } → 编译报错，必须先 (err as Error)。
  3. 用 for (const key in obj) 遍历对象属性 → ArkTS 禁用 for...in，改用 Object.keys(obj) + for...of。

题目 4 · 集合链式处理（对应概念 03） ​

难度：基础

题目：给定用户数组，实现「过滤成年人 → 提取名字 → 拼接成逗号分隔的字符串」，并统计「所有成年用户名字的字符总数」。

要求：

  • 两个结果都用链式调用（filter / map / reduce），reduce 必须给初始值
  • 数组用 Array<User> 显式泛型声明
  • 演示「不可变追加」（扩展运算符）与「可变追加」（push）的区别
  • 打印两个结果

提示：前端锚点——filter/map/reduce 与 JS 完全一致；差异是必须写泛型 Array<User>，且不允许混合类型数组。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

// 集合必须显式声明元素类型（ArkTS 禁用 any，也禁止混合类型数组）
const users: Array<User> = [
  { name: 'Alice', age: 30 },
  { name: 'Bob', age: 17 },
  { name: 'Charlie', age: 25 },
  { name: 'Dave', age: 40 }
];

// 1) 过滤 -> 提取 -> 拼接
const adultNameStr: string = users
  .filter((u: User) => u.age >= 18)
  .map((u: User) => u.name)
  .join(', ');
console.info(adultNameStr);   // Alice, Charlie, Dave

// 2) 过滤 -> 提取 -> 取长度 -> 累加（reduce 必须给初始值 0）
const totalLength: number = users
  .filter((u: User) => u.age >= 18)
  .map((u: User) => u.name)
  .map((name: string) => name.length)
  .reduce((sum: number, len: number) => sum + len, 0);
console.info(`${totalLength}`);   // 16

// 3) 不可变追加：扩展运算符生成新数组（推荐，状态更新更安全）
const added: User[] = [...users, { name: 'Eve', age: 22 }];
console.info(`${users.length}, ${added.length}`);   // 4, 5（原数组没变）

// 4) 可变追加：push 就地修改原数组
const mutable: User[] = [...users];
mutable.push({ name: 'Frank', age: 28 });
console.info(`${mutable.length}`);   // 5

要点解析：

  1. 集合的 API（filter / map / reduce / find / some / every）与 JS 完全一致，前端零成本迁移，只需补上类型注解。
  2. Array<User> 与 User[] 等价，但 ArkTS 要求显式泛型，不能写裸 []。
  3. 状态更新场景优先用扩展运算符（[...arr, item]）生成新数组——与声明式 UI 的「不可变更新更安全」一致。

常见错误：

  1. const arr = [1, 'a'] → 被推断为联合类型数组，不能当 number[] 使用。
  2. reduce((sum, len) => sum + len) 不给初始值 → 空数组会抛错，且 ArkTS 要求参数有类型。
  3. const users: Array<User> = []; users.push({ name: 'x' }) → 对象字面量缺 age，不符合 User 形状，编译报错。

题目 5 · 分组与计数（对应概念 03） ​

难度：进阶

题目：实现两个函数。

  1. groupByAgeRange(users: User[]): Map<string, User[]>：按「未成年（<18）/ 青年（18-44）/ 中年（>=45）」分组。
  2. countTags(tags: string[]): Map<string, number>：统计每个标签出现次数。

要求：

  • 用 Map / Set 实现，显式声明泛型（Map<string, User[]>）
  • 打印每组的用户名字列表，以及标签计数结果
  • 额外演示用 Set 给标签去重

提示：前端锚点——Map / Set 及方法与 JS 完全一致；差异是键和值都有类型约束，不能像 JS 那样随意塞。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

// 1) 分组：Map<string, User[]>，按年龄段归类
function groupByAgeRange(users: User[]): Map<string, User[]> {
  const result: Map<string, User[]> = new Map();
  for (const user of users) {
    let range: string = '中年';
    if (user.age < 18) {
      range = '未成年';
    } else if (user.age < 45) {
      range = '青年';
    }
    const bucket: User[] | undefined = result.get(range);
    if (bucket === undefined) {
      result.set(range, [user]);   // 第一次出现，新建数组
    } else {
      bucket.push(user);           // 已存在，追加
    }
  }
  return result;
}

// 2) 计数：Map<string, number>
function countTags(tags: string[]): Map<string, number> {
  const result: Map<string, number> = new Map();
  for (const tag of tags) {
    // Map.get 返回 V | undefined，用 ?? 给默认值 0
    result.set(tag, (result.get(tag) ?? 0) + 1);
  }
  return result;
}

const users: User[] = [
  { name: 'Alice', age: 30 },
  { name: 'Bob', age: 17 },
  { name: 'Charlie', age: 45 },
  { name: 'Dave', age: 22 }
];

groupByAgeRange(users).forEach((list: User[], range: string) => {
  console.info(`${range}: ${list.map((u: User) => u.name).join(', ')}`);
});
// 未成年: Bob
// 青年: Alice, Dave
// 中年: Charlie

const tags: string[] = ['js', 'ts', 'js', 'go', 'ts', 'js'];
countTags(tags).forEach((count: number, tag: string) => {
  console.info(`${tag}=${count}`);
});
// js=3  ts=2  go=1

// 3) Set 去重（与 JS 一致）
const uniqueTags: string[] = [...new Set(tags)];
console.info(uniqueTags.join(','));   // js,ts,go

要点解析：

  1. Map.get() 返回 V | undefined，所以「首次计数」要用 ?? 0 处理——这与 TS 严格模式完全一致。
  2. Map 的遍历用 forEach((value, key) => {})，注意参数顺序是「值在前、键在后」，与 Array.forEach 的「元素在前、下标在后」顺序不同，容易记混。
  3. Set + 扩展运算符是去重的最短写法：[...new Set(arr)]。

常见错误：

  1. const m = new Map(); 不写泛型 → ArkTS 无法推断类型，后续 set / get 会报错。
  2. result.get(tag) + 1 → 可能是 undefined + 1 得到 NaN，必须先 ?? 0。
  3. 把 Map.forEach 的参数顺序写成 (key, value) → 与 Array.forEach 记混，取到的是反的。

题目 6 · 第一个 async/await（对应概念 04） ​

难度：进阶

题目：实现 function fetchUser(id: number): Promise<User>，内部用 setTimeout 模拟 1 秒网络请求；再写一个 async 函数调用它并打印结果。

要求：

  • fetchUser 返回 Promise<User>，1 秒后 resolve；id <= 0 时 reject
  • 调用方用 async/await + try/catch
  • 打印「开始请求」→（1 秒后）→「获取到：User1」

提示：前端锚点——ArkTS 的异步与 JS 完全一致：Promise + async/await + 事件循环。这是三端里迁移成本最低的一块。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

// 返回 Promise 的异步函数（与 JS 写法完全一致）
function fetchUser(id: number): Promise<User> {
  return new Promise<User>((resolve: (u: User) => void, reject: (e: Error) => void) => {
    setTimeout(() => {
      if (id > 0) {
        resolve({ name: `User${id}`, age: 20 + id });
      } else {
        reject(new Error('无效的 ID'));
      }
    }, 1000);   // 1 秒后返回，模拟网络延迟
  });
}

// async/await 调用（await 只能在 async 函数内使用）
async function printUser(): Promise<void> {
  console.info('开始请求');
  try {
    const user: User = await fetchUser(1);   // 等待 1 秒
    console.info(`获取到：${user.name}，${user.age} 岁`);
  } catch (err) {
    console.error(`请求失败：${(err as Error).message}`);
  }
}

printUser();
// 开始请求
// （约 1 秒后）
// 获取到：User1，21 岁

要点解析：

  1. Promise 的 resolve / reject 回调在 ArkTS 中必须标注参数类型（(resolve: (u: User) => void, ...)），这是比 TS 更严格的地方。
  2. await 只能在 async 函数内使用——顶层 await 在 ArkTS 的 .ets 文件中通常不可用，要包一层 async 函数。
  3. 在 UI 组件里做异步，应放在生命周期钩子（如 aboutToAppear）中，并把结果赋给 @State 变量才会触发刷新（见 L2）。

常见错误：

  1. 在非 async 函数里写 await fetchUser(1) → 编译报错。
  2. new Promise((resolve, reject) => ...) 不标注回调参数类型 → ArkTS 严格模式下编译报错。
  3. 忘记 try/catch → 异步错误不会自动冒到顶层，失败时控制台只留一个 unhandled rejection，界面毫无反应。

题目 7 · 并发与竞速（对应概念 04） ​

难度：进阶

题目：实现 async function getUsers(ids: number[]): Promise<User[]>，用 Promise.all 并发获取所有用户并打印耗时；再用 Promise.race 实现一个 withTimeout 包装（超时 2 秒抛错）。

要求：

  • getUsers 用 ids.map(...) + Promise.all
  • withTimeout 用 Promise.race 实现（业务 Promise vs 定时拒绝的 Promise）
  • 打印并发耗时，说明为什么不是 ids.length × 1 秒

提示：前端锚点——Promise.all / Promise.race 与 JS 完全同名同语义，这就是前端的主场。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

function fetchUser(id: number): Promise<User> {
  return new Promise<User>((resolve: (u: User) => void) => {
    setTimeout(() => {
      resolve({ name: `User${id}`, age: 20 + id });
    }, 1000);
  });
}

// 并发：Promise.all（与 JS 完全一致）
async function getUsers(ids: number[]): Promise<User[]> {
  const promises: Array<Promise<User>> = ids.map((id: number) => fetchUser(id));
  const users: User[] = await Promise.all(promises);
  return users;
}

// 超时包装：业务 Promise 与「定时拒绝」竞速
function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  const timeout: Promise<T> = new Promise<T>((_resolve: (v: T) => void, reject: (e: Error) => void) => {
    setTimeout(() => reject(new Error(`请求超时（${ms}ms）`)), ms);
  });
  return Promise.race([promise, timeout]);
}

async function main(): Promise<void> {
  const start: number = Date.now();
  const users: User[] = await getUsers([1, 2, 3]);
  console.info(`并发获取 ${users.length} 个用户，耗时 ${Date.now() - start} ms`);
  // 并发获取 3 个用户，耗时约 1000 ms（三个请求同时发出，不是 3 秒）

  try {
    // 1 秒能返回，超时设 2 秒 -> 成功
    const ok: User = await withTimeout(fetchUser(1), 2000);
    console.info(`成功：${ok.name}`);
    // 业务需要 1 秒，超时设 500ms -> 抛超时错误
    await withTimeout(fetchUser(2), 500);
  } catch (err) {
    console.error(`失败：${(err as Error).message}`);
  }
}

main();

要点解析：

  1. ids.map((id) => fetchUser(id)) 会立即发起所有请求，所以三个 1 秒的任务并发跑完只花约 1 秒；写成 for 循环逐个 await 就是串行（3 秒）。
  2. Promise.race 谁先结束用谁的结果（成功或失败都算结束）——这就是超时控制的原理。
  3. 注意：竞速输掉的 Promise 不会被取消，底层请求仍在跑（只是结果被丢弃）；要真正取消需要 AbortController 之类的机制。

常见错误：

  1. 在 for 循环里 await fetchUser(id) 以为并发 → 实际串行，耗时翻倍。
  2. Promise.all 中一个失败就整体 reject → 需要「部分失败也继续」时用 Promise.allSettled。
  3. 以为 Promise.race 超时后原请求被取消 → 请求仍在继续，只是结果没人接收。

题目 8 · 空安全：可选链与类型收窄（对应概念 05） ​

难度：基础

题目：实现 findUser(users: User[], name: string): User | undefined，再写 describe(users, name): string：找到时返回 "姓名(年龄)"，找不到返回 "查无此人"。

要求：

  • 用 ?. 可选链和 ?? 空值合并
  • 用 if (x !== null) / if (x !== undefined) 演示类型收窄
  • 覆盖两种情形：找得到、找不到，都要打印验证
  • 区分「可选属性 address?」与「可空类型 string | null」两种「可能为空」

提示：前端锚点——?. 与 ?? 和 JS 完全一致；差异是 ArkTS 在编译期强制你处理，且可选属性（可能 undefined）与可空类型（明确 null）是两种不同的写法。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

interface UserProfile {
  address?: {      // 可选属性：可能 undefined，用 ? 标记
    city: string;
    zip?: string;  // 嵌套可选属性
  };
}

// 返回联合类型：找到返回 User，找不到返回 undefined
function findUser(users: User[], name: string): User | undefined {
  return users.find((u: User) => u.name === name);
}

function describe(users: User[], name: string): string {
  const user: User | undefined = findUser(users, name);
  // 可选链 + 空值合并：user 为 undefined 时整条链短路为 undefined，再 ?? 兜底
  return user?.name !== undefined ? `${user.name}(${user.age})` : '查无此人';
}

const users: User[] = [{ name: 'Alice', age: 30 }, { name: 'Bob', age: 17 }];
console.info(describe(users, 'Alice'));   // Alice(30)
console.info(describe(users, 'Zoe'));     // 查无此人

// 类型收窄：if 检查后编译器自动把类型收窄为非空
function printLength(text: string | null): void {
  if (text !== null) {
    console.info(`长度：${text.length}`);   // 这里 text 已被收窄为 string
  } else {
    console.info('没有内容');
  }
}
printLength('hello');   // 长度：5
printLength(null);      // 没有内容

// 可选属性要用可选链访问，否则可能拿到 undefined
const profile: UserProfile = {};
const city: string | undefined = profile?.address?.city;         // undefined，不崩溃
const zip: string = profile?.address?.zip ?? '未知';              // 未知
console.info(`${city ?? '未填城市'} / ${zip}`);

要点解析：

  1. 「可选属性 address?: T」表示可能 undefined；「可空类型 string | null」表示可能是明确的 null——两者是不同的「空」，访问时都要先处理。
  2. ?. 可选链会在任意一环为 null/undefined 时短路返回 undefined，?? 只针对 null/undefined 兜底（'' 和 0 不会被替换，与 || 不同）。
  3. 类型收窄靠 if (x !== null) 或 if (x !== undefined)，编译器在块内自动把类型收窄为非空——这是 ArkTS 严格模式下的核心安全网。

常见错误：

  1. profile.address.city 直接访问可选属性 → 编译报错（可能为 undefined）。
  2. 用 || 代替 ?? 做兜底 → '' 和 0 会被误判为「空」而被替换，这是 TS/JS 的经典坑。
  3. catch (err) { err.message } → err 是 unknown，必须 (err as Error).message。

题目 9 · 错误处理：自定义错误与 try/catch（对应概念 05） ​

难度：基础

题目：定义 class DivideError extends Error，实现 divide(a: number, b: number): number（除数为 0 时抛 DivideError）；调用方用 try/catch/finally 捕获并打印错误信息，异常时返回 0。

要求：

  • 自定义错误类继承 Error 并设置 name
  • catch 中用类型断言 (err as Error) 访问 message
  • finally 里打印「计算结束」，验证无论成功失败都会执行
  • 额外演示 async 函数中的错误捕获（try 包住 await）

提示：前端锚点——try/catch/finally 与 JS 完全一致；唯一差异是 ArkTS 的 catch 变量是 unknown，需要类型断言。

参考答案
typescript
// 自定义错误类：继承 Error，设置 name 便于区分
class DivideError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'DivideError';
  }
}

function divide(a: number, b: number): number {
  if (b === 0) {
    throw new DivideError('除数不能为零');
  }
  return a / b;
}

function safeDivide(a: number, b: number): number {
  try {
    return divide(a, b);
  } catch (err) {
    // catch 变量是 unknown，类型断言后才能访问 .message
    console.error(`捕获到错误：${(err as Error).message}`);
    return 0;
  } finally {
    console.info('计算结束');   // 无论成功失败都会执行
  }
}

console.info(`${safeDivide(10, 2)}`);   // 计算结束 → 5
console.info(`${safeDivide(10, 0)}`);   // 捕获到错误：除数不能为零 → 计算结束 → 0

// 异步错误捕获：必须在 try 块内 await，否则 catch 不到
async function asyncDivide(): Promise<number> {
  try {
    const result: number = await Promise.resolve(divide(10, 0));
    return result;
  } catch (err) {
    console.error(`异步捕获：${(err as Error).name} - ${(err as Error).message}`);
    return 0;
  }
}
asyncDivide();   // 异步捕获：DivideError - 除数不能为零

要点解析：

  1. throw 可以抛任何值，但工程上应抛 Error 的子类（带 name、message、stack，便于日志与上报）。
  2. 异步错误必须在 try 块内 await 才能被捕获；写成 const p = fetch(); try { return p } catch {} 捕获不到。
  3. finally 无论成功失败都会执行，适合放资源释放（如网络请求的 destroy()），不能放「只有成功才做」的逻辑。

常见错误：

  1. catch (err) { console.error(err.message) } → 编译报错，err 是 unknown。
  2. async 函数里漏掉 await 就 try/catch → 捕获不到，错误变成 unhandled rejection。
  3. 空 catch {} 静默吞掉异常 → 出错时无从排查，至少要 console.error 或上报。

题目 10 · 综合：带超时重试的安全查询（对应概念 04 + 05） ​

难度：综合

题目：实现 async function safeGetUser(id: number): Promise<string>，串联空安全、错误处理与异步：

  1. ID 小于等于 0 → 抛 ValidationError
  2. 用题目 7 的 withTimeout 包住 fetchUser，超时 2 秒后重试，最多 3 次
  3. 3 次都失败 → 返回 "未找到用户（已重试 3 次）"，不崩溃、不静默
  4. 成功 → 返回 "找到：User1"

要求：

  • 每次失败都打印原因（超时 / 其他错误）
  • 用 User | null 表达「没有结果」，而不是返回假数据
  • 全程不使用 any、不使用非空断言 !
  • 验证两种输入：1（成功）、-1（抛参数错误，用 try/catch 兜住）

提示：前端锚点——这就是 TS 严格模式下的「Promise.race 超时 + 重试循环 + 联合类型收窄」，写法与前端完全一致。

参考答案
typescript
interface User {
  name: string;
  age: number;
}

class ValidationError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'ValidationError';
  }
}

function fetchUser(id: number): Promise<User> {
  return new Promise<User>((resolve: (u: User) => void) => {
    // id 为 999 时模拟「慢到超时」
    setTimeout(() => resolve({ name: `User${id}`, age: 20 + id }), id === 999 ? 3000 : 1000);
  });
}

function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  const timeout: Promise<T> = new Promise<T>((_resolve: (v: T) => void, reject: (e: Error) => void) => {
    setTimeout(() => reject(new Error(`请求超时（${ms}ms）`)), ms);
  });
  return Promise.race([promise, timeout]);
}

// 带重试的获取：成功返回 User，三次都失败返回 null（用联合类型表达「没有结果」）
async function fetchWithRetry(id: number, maxRetry: number = 3): Promise<User | null> {
  for (let attempt = 1; attempt <= maxRetry; attempt++) {
    try {
      return await withTimeout(fetchUser(id), 2000);
    } catch (err) {
      // 打印原因，绝不静默吞掉
      console.error(`第 ${attempt} 次请求失败：${(err as Error).message}`);
    }
  }
  return null;
}

async function safeGetUser(id: number): Promise<string> {
  // 参数校验：调用方传错就抛，属于「程序的错」而非业务分支
  if (id <= 0) {
    throw new ValidationError(`ID 必须为正数，收到 ${id}`);
  }

  const user: User | null = await fetchWithRetry(id);
  // 类型收窄：user 为 null 时走兜底文案
  if (user !== null) {
    return `找到：${user.name}`;
  }
  return '未找到用户（已重试 3 次）';
}

async function main(): Promise<void> {
  console.info(await safeGetUser(1));     // 找到：User1

  console.info(await safeGetUser(999));
  // 第 1 次请求失败：请求超时（2000ms）
  // 第 2 次请求失败：请求超时（2000ms）
  // 第 3 次请求失败：请求超时（2000ms）
  // 未找到用户（已重试 3 次）

  try {
    await safeGetUser(-1);
  } catch (err) {
    console.error(`参数错误：${(err as Error).message}`);   // 参数错误：ID 必须为正数，收到 -1
  }
}

main();

要点解析：

  1. 用类型表达结果：「可能没有」用 User | null；「调用方传错」用抛异常。前者是正常业务分支，后者是编程错误，两者不要混用。
  2. 重试循环里每次失败都要留下痕迹（打印或上报），静默重试 3 次后返回一个 null，用户只会觉得「莫名没有数据」，排查成本极高。
  3. Promise.race 超时后原请求并未取消（仍会 resolve），只是结果被丢弃——生产环境要考虑请求取消或幂等。

常见错误：

  1. 重试失败时返回「假用户」{ name: '', age: 0 } → 调用方无法区分「查无此人」与「请求失败」。
  2. catch 里什么都不做 → 静默吞异常，是「不崩溃」的错误实现方式。
  3. const user = await fetchWithRetry(id); console.info(user.name) → user 可能是 null，编译报错（这正是编译期空安全在保护你）。
