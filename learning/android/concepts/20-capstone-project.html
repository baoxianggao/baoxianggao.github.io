20 · 综合实战项目 ​

概念简介 ​

本篇是全系列的综合实战，目标是用一个待办清单 App串联前 19 个概念：声明式 UI（06-13）、网络请求（14）、本地存储（15）、异步编程（04）、状态管理（09）、权限与后台任务（19）。通过完整实现一个功能一致的待办 App，巩固所学，检验学习成果。

项目功能 ​

  • 待办 CRUD：新增、编辑、删除、标记完成
  • 本地持久化：离线可用，App 重启数据不丢
  • 分类管理：按分类筛选待办
  • 网络同步（可选）：与后端同步，多设备数据一致

核心内容 ​

技术栈映射：Compose（06-13 声明式 UI）+ Room（15 本地存储）+ Retrofit（14 网络请求）+ ViewModel（09 状态管理）。

关键代码片段：

kotlin
// data/Todo.kt -- Room 实体 + 数据类（02 篇 + 15 篇）
@Entity(tableName = "todos")
data class Todo(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val category: String,
    val done: Boolean = false,
    val createdAt: Long = System.currentTimeMillis()
)

// data/TodoDao.kt -- 数据访问对象（15 篇）
@Dao
interface TodoDao {
    @Query("SELECT * FROM todos ORDER BY createdAt DESC")
    fun getAllTodos(): Flow<List<Todo>>  // Flow 响应式（04 篇）

    @Insert
    suspend fun insert(todo: Todo): Long  // 挂起函数（04 篇）

    @Update
    suspend fun update(todo: Todo)

    @Delete
    suspend fun delete(todo: Todo)
}

// network/TodoApi.kt -- Retrofit 接口（14 篇）
interface TodoApi {
    @GET("todos")
    suspend fun getTodos(): List<TodoDto>

    @POST("todos")
    suspend fun createTodo(@Body todo: TodoDto): TodoDto

    @PUT("todos/{id}")
    suspend fun updateTodo(@Path("id") id: Long, @Body todo: TodoDto): TodoDto

    @DELETE("todos/{id}")
    suspend fun deleteTodo(@Path("id") id: Long)
}

// ui/TodoViewModel.kt -- 状态管理（09 篇）
class TodoViewModel(
    private val repository: TodoRepository
) : ViewModel() {
    // StateFlow 响应式状态（类比 zustand 的 store）
    val todos: StateFlow<List<Todo>> = repository.allTodos
        .stateIn(viewModelScope, SharingStarted.Lazily, emptyList())

    fun addTodo(title: String, category: String) {
        viewModelScope.launch {  // 协程（04 篇）
            repository.insert(Todo(title = title, category = category))
        }
    }

    fun toggleTodo(todo: Todo) {
        viewModelScope.launch {
            repository.update(todo.copy(done = !todo.done))  // 不可变更新
        }
    }

    fun deleteTodo(todo: Todo) {
        viewModelScope.launch { repository.delete(todo) }
    }
}

// ui/TodoScreen.kt -- 列表页（10 篇 列表渲染 + 07 篇 布局）
@Composable
fun TodoScreen(viewModel: TodoViewModel) {
    val todos by viewModel.todos.collectAsState()  // 收集状态
    var input by remember { mutableStateOf("") }   // 输入框状态（09 篇）

    Column(modifier = Modifier.padding(16.dp)) {
        // 输入区（12 篇 表单）
        Row {
            TextField(
                value = input,
                onValueChange = { input = it },
                label = { Text("新待办") }
            )
            Button(onClick = {
                if (input.isNotBlank()) {
                    viewModel.addTodo(input, "默认")
                    input = ""
                }
            }) { Text("添加") }
        }
        // 列表区（10 篇 虚拟滚动）
        LazyColumn {
            items(todos) { todo ->
                TodoItem(
                    todo = todo,
                    onToggle = { viewModel.toggleTodo(todo) },
                    onDelete = { viewModel.deleteTodo(todo) }
                )
            }
        }
    }
}

  1. build.gradle.kts 添加依赖（Room / Retrofit / Coroutines / Compose）
  2. 定义 Todo 实体 + TodoDao + TodoDatabase（15 篇）
  3. 定义 TodoApi Retrofit 接口 + TodoRepository 仓库（14 篇）
  4. 实现 TodoViewModel 状态管理（09 篇）
  5. 编写 TodoScreen + TodoItem UI（06-13 篇）
  6. 在 MainActivity 中绑定 ViewModel（01 篇）

常见陷阱 ​

  • Android：Room 的 Flow 响应式查询非常方便（数据变了自动刷新 UI），但陷阱是 Flow 是冷流，需 stateIn 转成热流才能在 ViewModel 中持有。Retrofit 的 suspend 函数自动在后台线程执行，但 Room 默认禁止主线程操作数据库，需用协程切换。Compose 的 remember 状态在配置变更（旋转屏幕）后会丢失，持久状态用 rememberSaveable 或 ViewModel。
  • 跨端共性陷阱：本地存储的「ID 策略」需统一--Android 用自增 Long。网络请求地址在真机测试时不能用 localhost，要用电脑局域网 IP（如 192.168.1.x）。

练习建议（分阶段实现） ​

阶段一：后端先行 ​

  1. 搭建后端项目（如 FastAPI + SQLite），实现 Todo CRUD 四个端点
  2. 用自动文档测试每个端点，确保返回格式正确
  3. 添加分类字段，支持按分类筛选 GET /api/todos?category=工作

阶段二：单端 MVP ​

  1. 实现 Android 本地 CRUD（Room）
  2. 接入后端 API，实现网络加载待办 + 本地缓存
  3. 实现输入框 + 列表 + 完成切换 + 删除，跑通核心流程

阶段三：进阶能力 ​

  1. 加后台同步任务（19 篇）：Android WorkManager
  2. 加通知提醒（19 篇）：待办可设截止时间，到期推送本地通知
  3. 加单元测试（17 篇）：为 ViewModel / Repository / API 层各写测试，覆盖率 80%+

阶段四：资深层进阶（L4/L5 目标） ​

利用阶段 5 的资深概念，把待办 App 升级为生产级应用。这一阶段是 L4/L5 考核的项目载体，做完后应能用 /assess android L4 或 /assess android L5 验证。

  1. 架构分层落地（21 篇）：确认项目已按 UI → ViewModel → Repository → DataSource 分层；把 ViewModel 改造成 MVI 状态机（sealed interface 表达 UI 状态 + 意图），错误统一走 Result 封装。
  2. 依赖注入（22 篇）：引入 Hilt，用 @HiltViewModel + @Module + @Provides 注入 Repository、网络客户端、数据库；移除手动构造依赖的代码。
  3. 性能优化（23 篇）：用 derivedStateOf 收窄列表高频变化；检查 LazyColumn 的 key；用 Layout Inspector 实测重组次数并降到合理水平；处理输入框抖动。
  4. 崩溃与内存治理（24/25 篇）：接入 Crashlytics + LeakCanary；写一个能复现崩溃/泄漏的测试场景并修复；用 Memory Profiler 验证无 Activity 泄漏。
  5. 安全与发布（26 篇）：配置混淆规则；处理签名；按 buildTypes/flavors 区分 debug/release；对网络请求做证书固定。
  6. 国际化与无障碍（27 篇）：把字符串抽到 strings.xml 并支持至少 2 种语言；补 contentDescription 与无障碍语义。

阶段五：架构设计文档（L5 考核必备） ​

为你的项目写一份架构设计文档（docs/architecture.md），包含：

  • 架构分层图与各层职责
  • 关键技术选型与取舍论证（为什么用 Room 而不是 DataStore？为什么用 MVI 而不是简单 ViewModel？）
  • 数据流描述（从用户操作到状态更新的完整链路）
  • 性能与安全考量清单
  • 已知限制与后续演进
