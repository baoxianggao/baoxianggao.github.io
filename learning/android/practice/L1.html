题目 1 · 跑通第一个程序并拆出组件（对应概念 01） ​

难度：基础

题目：新建一个 Empty Compose Activity 项目，把屏幕上的文字改成「Hello, 张三」，并把它抽成一个独立的 @Composable 函数 Greeting(name: String)，在入口里调用两次（传入不同名字）。再加一个按钮，点击后在 Logcat 输出一行日志。

要求：

  • 入口 MainActivity 用 setContent { } 设置内容
  • 两个名字纵向排列（用 Column）
  • 按钮点击后用 Log.d("MainActivity", "...") 输出日志，能在 Logcat 搜到
  • 能说清 MainActivity 的职责是什么

提示：前端锚点——setContent {} 就是 React 的 createRoot().render(<App />)，@Composable 函数就是函数组件，函数参数就是 props。

参考答案
kotlin
// app/src/main/java/com/example/myapp/MainActivity.kt
package com.example.myapp

import android.os.Bundle
import android.util.Log
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.foundation.layout.Column
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // setContent：把 Compose 内容挂到 Activity 上，类比 React 挂载根组件
        setContent {
            Column {
                Greeting(name = "张三")
                Greeting(name = "李四")
                Button(onClick = { Log.d("MainActivity", "按钮被点击了") }) {
                    Text("打个招呼")
                }
            }
        }
    }
}

// @Composable 函数 = 一个组件；参数就是 props，可以被复用
@Composable
fun Greeting(name: String) {
    Text(text = "Hello, $name")
}

要点解析：

  1. MainActivity 的职责是「作为应用入口，在 onCreate 里用 setContent 挂载 Compose 视图树」，除此之外不应该堆业务逻辑。
  2. @Composable 注解把普通函数变成视图函数，首字母大写是社区规范（编译器会按组件检查）。
  3. Column 类比 <div style="display:flex; flex-direction:column">，子元素按顺序纵向排列。

常见错误：

  1. 忘了加 @Composable 注解 → 报「@Composable invocations can only happen from the context of a @Composable function」。
  2. 把 Greeting(name = "张三") 写成 Greeting("张三") 之外的命名参数混乱——Kotlin 支持命名参数，写全可读性更好。
  3. 在 setContent 外面调用 @Composable 函数（如在 onCreate 里直接写 Text(...)）→ 同样报上下文错误。

题目 2 · 数据类与字符串模板（对应概念 02） ​

难度：基础

题目：定义 User 数据结构（含 name: String、age: Int），写一个 formatUser(user: User): String 返回 "姓名(年龄)"，再写 adultNames(users: List<User>): List<String> 返回所有成年用户的名字。

要求：

  • User 用 data class（体会自动生成 equals/toString/copy）
  • 用字符串模板 "$name" / "${expr}" 拼接，不要用 +
  • 创建 3 个实例（含 1 个未成年），打印 formatUser 的结果和成年用户列表

提示：前端锚点——data class ≈ 一个自动带 toString 的 interface + 对象字面量；${} 与 JS 模板字符串写法几乎一样。

参考答案
kotlin
// 数据类：一行搞定数据载体，自动生成 equals / hashCode / toString / copy
data class User(val name: String, val age: Int)

// 表达式函数体：返回值类型写在参数后面
fun formatUser(user: User): String = "${user.name}(${user.age})"

fun adultNames(users: List<User>): List<String> =
    users.filter { it.age >= 18 }   // it 是 lambda 的隐式参数名
        .map { it.name }

fun main() {
    val users = listOf(
        User("Alice", 30),
        User("Bob", 17),
        User("Charlie", 25)
    )

    users.forEach { println(formatUser(it)) }
    // Alice(30)
    // Bob(17)
    // Charlie(25)

    println(adultNames(users))   // [Alice, Charlie]

    // data class 自带解构（按属性声明顺序）
    val (name, age) = users[0]
    println("$name 今年 $age 岁")

    // data class 自带 copy（不可变更新：改一个字段，其余保留）
    val older = users[0].copy(age = 31)
    println(formatUser(older))   // Alice(31)
}

要点解析：

  1. val 是不可变引用（类比 const），var 可变；默认写 val，需要改才用 var。
  2. data class 的属性一旦用 val 声明就不能改，要「改」请用 copy() 生成新对象——这是不可变思维的语言级支持。
  3. Kotlin 的 if 是表达式、没有三元运算符，when 同理，这一特点在题目 3 会用到。

常见错误：

  1. val x = 1; x = "a" → 类型推导后类型固定，编译报错（JS 习惯了动态切换会踩）。
  2. 写成 "姓名：" + user.name + "(" + user.age + ")"——能跑但不地道，字符串模板更清晰。
  3. 以为 val 声明的对象内部也不可变：val list = mutableListOf(1); list.add(2) 是合法的（引用不可变 ≠ 内容不可变），和 JS 的 const 完全一致。

题目 3 · when 与区间（对应概念 02） ​

难度：基础

题目：写 fun grade(score: Int): String，按分数返回等级：0-59「不及格」、60-79「及格」、80-89「良好」、90-100「优秀」，分数超出 0-100 抛出 IllegalArgumentException。

要求：

  • 必须用 when + 区间（in a..b）
  • 采用表达式函数体（= when { ... }）
  • 写 5 个用例验证：45 / 60 / 85 / 100 / 101（最后一个要能捕获异常）

提示：前端锚点——when 是强化版 switch，能判断区间且分支不贯穿（不用写 break），还能当 if-else 链用。

参考答案
kotlin
fun grade(score: Int): String = when (score) {
    in 0..59   -> "不及格"
    in 60..79  -> "及格"
    in 80..89  -> "良好"
    in 90..100 -> "优秀"
    else -> throw IllegalArgumentException("分数必须在 0-100 之间，收到：$score")
}

fun main() {
    val scores = listOf(45, 60, 85, 100, 101)
    for (score in scores) {
        // try/catch 捕获非法输入，不让整个程序崩掉
        val result = try {
            grade(score)
        } catch (e: IllegalArgumentException) {
            "错误：${e.message}"
        }
        println("$score -> $result")
    }
    // 45 -> 不及格
    // 60 -> 及格
    // 85 -> 良好
    // 100 -> 优秀
    // 101 -> 错误：分数必须在 0-100 之间，收到：101
}

要点解析：

  1. .. 是闭区间，0..59 包含 59；想左闭右开要写 until（0 until 60）。这一点与 Python 的 range 相反，跨语言最容易记混。
  2. when 用作表达式（有返回值）时，else 必须写，否则编译不过——这里是「抛异常」而不是给默认值，属于主动防御。
  3. when 也可以不带参数，每个分支写独立布尔判断（when { score < 60 -> ... }），等价于 if-else 链。

常见错误：

  1. 想循环 5 次写 for (i in 0..5) → 实际跑 6 次（含两端），应该是 0 until 5 或 0..4。
  2. 用 switch 语法（Kotlin 没有 switch 关键字）或在分支末尾加 break。
  3. when 作表达式却漏掉 else → 编译报错 "'when' expression must be exhaustive"。

题目 4 · 集合链式处理（对应概念 03） ​

难度：基础

题目：给定用户列表，实现「过滤成年人 → 提取名字 → 拼接成逗号分隔的字符串」，再统计「所有成年用户名字的字符总数」。

要求：

  • 两个结果都用链式调用实现（filter / map / reduce）
  • 明确区分只读 List 与可变 MutableList：数据源用 listOf，需要增删时才 toMutableList()
  • 打印两个结果

提示：前端锚点——list.filter{}.map{} 与 arr.filter().map() 完全一致，唯一区别是 lambda 用 {}、隐式参数叫 it。

参考答案
kotlin
data class User(val name: String, val age: Int)

fun main() {
    // 只读集合：listOf 返回 List，不能 add/remove
    val users: List<User> = listOf(
        User("Alice", 30),
        User("Bob", 17),
        User("Charlie", 25),
        User("Dave", 40)
    )

    // 1) 过滤 -> 提取 -> 拼接
    val adultNameStr: String = users
        .filter { it.age >= 18 }
        .map { it.name }
        .joinToString(", ")
    println(adultNameStr)   // Alice, Charlie, Dave

    // 2) 过滤 -> 提取 -> 取长度 -> 累加
    val totalLength: Int = users
        .filter { it.age >= 18 }
        .map { it.name }
        .map { it.length }
        .reduce { acc, len -> acc + len }
    println(totalLength)    // 5 + 7 + 4 = 16

    // 3) 需要增删时，先转成可变集合（不要直接对 List 调 add）
    val mutableUsers = users.toMutableList()
    mutableUsers.add(User("Eve", 22))
    mutableUsers.removeAt(0)
    println(mutableUsers)   // [User(name=Charlie,...), User(name=Dave,...), User(name=Eve,...)]

    // 4) 不可变更新：plus 返回新 List，原集合不变
    val added: List<User> = users + User("Frank", 28)
    println(users.size)     // 4（原集合没变）
    println(added.size)     // 5
}

要点解析：

  1. List 是只读接口、MutableList 是可变接口，二者是两个类型，listOf 返回只读 List。默认用只读，需要修改再 toMutableList()。
  2. 「只读 ≠ 深不可变」：只读接口只是不暴露修改方法，底层对象可能被其他可变引用改动，这一点心里要有数。
  3. reduce 从第一个元素开始累加（空集合会抛异常），需要初始值用 fold(0) { acc, len -> acc + len }。

常见错误：

  1. 直接写 users.add(...) → List 没有 add 方法，编译报错。
  2. val list = mutableListOf<User>() 后又写 val l: List<User> = list; l.add(...) → 只读视图上仍不能 add。
  3. 空集合上调 reduce → 运行时抛 UnsupportedOperationException（空集合用 fold 更安全）。

题目 5 · 分组与计数（对应概念 03） ​

难度：进阶

题目：实现两个函数。

  1. groupByAgeRange(users)：按「未成年（<18）/ 青年（18-44）/ 中年（>=45）」分组，返回 Map<String, List<User>>。
  2. countTags(tags: List<String>): Map<String, Int>：统计每个标签出现的次数（体会键值集合 API）。

要求：

  • 第 1 题用 groupBy，第 2 题手写循环（体会 ?: 处理首次计数）
  • 打印分组结果中每组的名字列表，以及标签计数结果

提示：前端锚点——groupBy 相当于 reduce 手搓分组的语法糖；countTags 就是 JS 里 tags.reduce((m, t) => (m[t] = (m[t]||0)+1, m), {})。

参考答案
kotlin
data class User(val name: String, val age: Int)

fun groupByAgeRange(users: List<User>): Map<String, List<User>> =
    users.groupBy { user ->
        when (user.age) {
            in 0..17  -> "未成年"
            in 18..44 -> "青年"
            else      -> "中年"
        }
    }

fun countTags(tags: List<String>): Map<String, Int> {
    val result = mutableMapOf<String, Int>()
    for (tag in tags) {
        // result[tag] 返回 Int?（首次为 null），用 Elvis 给默认值 0
        result[tag] = (result[tag] ?: 0) + 1
    }
    return result
}

fun main() {
    val users = listOf(
        User("Alice", 30), User("Bob", 17),
        User("Charlie", 45), User("Dave", 22)
    )

    val grouped = groupByAgeRange(users)
    for ((range, list) in grouped) {
        println("$range: ${list.map { it.name }}")
    }
    // 青年: [Alice, Dave]
    // 未成年: [Bob]
    // 中年: [Charlie]

    val tags = listOf("js", "ts", "js", "go", "ts", "js")
    println(countTags(tags))   // {js=3, ts=2, go=1}

    // 官方简写（了解即可）：groupingBy + eachCount
    println(tags.groupingBy { it }.eachCount())   // {js=3, ts=2, go=1}
}

要点解析：

  1. groupBy { keySelector } 返回 Map<K, List<T>>，key 由 lambda 计算——把 when 写在 lambda 里就能按任意规则分组。
  2. Map 取值 map[key] 返回可空类型 V?，所以 (result[tag] ?: 0) + 1 是标准写法；直接 result[tag] + 1 编译不过（Int? + Int 不允许）。
  3. groupingBy { }.eachCount() 是标准库的语法糖，写业务时优先用它，手写循环的价值是理解原理。

常见错误：

  1. result[tag] + 1 → 可空类型参与运算，编译报错。
  2. 用 mutableMapOf 却在函数签名写 Map<String, Int> 返回后又想改 → 只读视图不能改，要改就保留 MutableMap 类型。
  3. 分组时 when 漏掉 else 且用表达式写法 → 编译报错（这里 else 覆盖了 >=45 的所有情况）。

题目 6 · 第一个协程（对应概念 04） ​

难度：进阶

题目：实现 suspend fun fetchUser(id: Int): User，内部 delay(1000) 模拟网络请求（1 秒），然后在 main 里调用它并打印结果。

要求：

  • fetchUser 必须是 suspend 函数
  • main 用 runBlocking 包起来（这是「在普通函数里调用 suspend」的唯一合法入口之一）
  • 打印「开始请求」→（1 秒后）→「获取到：User1」

提示：前端锚点——suspend 函数 ≈ async function，delay(1000) ≈ await sleep(1000)（但不阻塞线程），runBlocking ≈ 顶层 async IIFE。

参考答案
kotlin
import kotlinx.coroutines.*

data class User(val name: String, val age: Int)

// suspend 标记「这个函数可挂起」，只能在协程里调用
suspend fun fetchUser(id: Int): User {
    delay(1000)   // 挂起 1 秒，不阻塞底层线程（类比 await sleep）
    return User("User$id", 20 + id)
}

fun main() = runBlocking {   // runBlocking 把普通 main 函数变成协程作用域
    println("开始请求")
    val user = fetchUser(1)  // 挂起点：协程在这里让出线程，1 秒后恢复
    println("获取到：${user.name}，${user.age} 岁")
}
// 输出：
// 开始请求
// （等待约 1 秒）
// 获取到：User1，21 岁

要点解析：

  1. suspend 是编译期标记：普通函数里直接调 fetchUser(1) 会编译报错，必须包在协程作用域（runBlocking / launch / async）里。
  2. delay() 与 Thread.sleep() 的本质区别：delay 挂起协程、线程可以去干别的活；sleep 会把线程整个占住（Android 主线程上就是卡 UI）。
  3. runBlocking 会阻塞当前线程，只用于 main 函数、单元测试或桥接旧代码，不要在 UI 线程用。

常见错误：

  1. 在 fun main()（非 suspend、非 runBlocking）里直接调 fetchUser(1) → 编译报错「Suspend function 'fetchUser' should be called only from a coroutine」。
  2. 用 Thread.sleep(1000) 代替 delay(1000) → 能跑但会阻塞线程，在 Android 上就是 ANR 的来源。
  3. 忘记 import kotlinx.coroutines.* → delay / runBlocking 报 unresolved reference。

题目 7 · 并发获取多个用户（对应概念 04） ​

难度：进阶

题目：在上题基础上实现 suspend fun getUsers(ids: List<Int>): List<User>，用 async + awaitAll() 并发获取所有用户，并打印总耗时，与「逐个 await 的串行写法」对比。

要求：

  • 用 coroutineScope { } 包裹（async 需要在协程作用域内启动）
  • 打印并发耗时，并说明为什么不是 ids.size × 1000ms
  • 额外要求：把耗时操作切到 Dispatchers.IO，体会线程切换

提示：前端锚点——async { } ≈ 启动一个 Promise 但先不 await，awaitAll() ≈ await Promise.all(...)。

参考答案
kotlin
import kotlinx.coroutines.*

data class User(val name: String, val age: Int)

suspend fun fetchUser(id: Int): User {
    delay(1000)
    return User("User$id", 20 + id)
}

// 并发版本：所有请求同时发出，总耗时 ≈ 最慢那一个
suspend fun getUsers(ids: List<Int>): List<User> = coroutineScope {
    // async 立刻启动并发任务，返回 Deferred（类比未 await 的 Promise）
    val deferreds = ids.map { id ->
        async(Dispatchers.IO) { fetchUser(id) }   // 切到 IO 线程做「网络请求」
    }
    deferreds.awaitAll()   // 等待全部完成，类比 await Promise.all
}

// 串行版本（对照）：每个请求等上一个完成
suspend fun getUsersSerial(ids: List<Int>): List<User> {
    val result = mutableListOf<User>()
    for (id in ids) {
        result.add(fetchUser(id))   // 逐个挂起等待
    }
    return result
}

fun main() = runBlocking {
    val ids = listOf(1, 2, 3)

    var start = System.currentTimeMillis()
    val users = getUsers(ids)
    println("并发：${users.map { it.name }}，耗时 ${System.currentTimeMillis() - start} ms")

    start = System.currentTimeMillis()
    getUsersSerial(ids)
    println("串行：耗时 ${System.currentTimeMillis() - start} ms")
}
// 并发：[User1, User2, User3]，耗时约 1010 ms
// 串行：耗时约 3020 ms

要点解析：

  1. async 启动的协程立即开始执行，不用等 await；所以三个 1 秒的任务并发跑完只花约 1 秒。
  2. awaitAll() 会等所有任务完成；其中一个失败会抛异常，需要 try/catch 或 supervisorScope 处理（见题目 10）。
  3. Dispatchers.IO 把任务切到 IO 线程池（适合网络/文件），执行完自动切回原线程——这是 JS 单线程世界里没有的概念。

常见错误：

  1. 在 coroutineScope 外直接写 async { } → 编译报错，async 是 CoroutineScope 的扩展函数。
  2. 写成 ids.map { fetchUser(it) } 以为并发 → 这是串行，suspend 调用是顺序等待的，必须 async 包一层。
  3. 用 GlobalScope.async → 脱离结构化并发，任务生命周期不受控，容易造成泄漏（初学阶段一律用 coroutineScope）。

题目 8 · 空安全：安全解包（对应概念 05） ​

难度：基础

题目：实现 findUser(users, name): User?，在列表中按名字查找（找不到返回 null）；再写 describe(users, name): String，找到时返回 "姓名(年龄)"，找不到返回 "查无此人"。

要求：

  • 用 ?. 安全调用或 ?.let { } 安全作用域
  • 不允许出现 !!
  • 覆盖两种情形：找得到、找不到，都要打印验证

提示：前端锚点——?. 与 JS 可选链一致，?: 与 ?? 一致；区别是 Kotlin 在编译期就能拦住你漏处理 null。

参考答案
kotlin
data class User(val name: String, val age: Int)

// 返回可空类型 User?：找不到就返回 null（类比 JS 的 undefined）
fun findUser(users: List<User>, name: String): User? =
    users.find { it.name == name }

fun describe(users: List<User>, name: String): String {
    val user: User? = findUser(users, name)

    // 写法一：?.let 安全作用域——只在非空时执行块，块内 it 已是非空 User
    val brief: String? = user?.let { "${it.name}(${it.age})" }

    // 写法二：Elvis 给默认值，保证最终返回非空 String
    return brief ?: "查无此人"
}

fun main() {
    val users = listOf(User("Alice", 30), User("Bob", 17))

    println(describe(users, "Alice"))  // Alice(30)
    println(describe(users, "Zoe"))    // 查无此人

    // 其他常用空安全写法
    val nickname: String? = null
    println(nickname?.uppercase())          // null（安全调用，不崩溃）
    println(nickname?.length ?: 0)          // 0（Elvis 兜底）
    println(nickname ?: "匿名")             // 匿名
}

要点解析：

  1. 类型后面加 ? 才是可空类型；String 与 String? 是两个类型，前者不能赋 null。
  2. ?.let { } 是 Kotlin 惯用法：比 if (x != null) 更优雅，块内变量已自动收窄为非空类型。
  3. !! 是「我担保它不为空」的断言，为 null 时抛 NullPointerException——生产代码里出现 !! 基本等于埋了一颗雷。

常见错误：

  1. 直接 user.name → 编译报错「Only safe (?.) or non-null asserted (!!.) calls are allowed」。
  2. 用 user!!.name 图省事 → 找不到用户时直接崩溃，违背本题「不崩溃」的要求。
  3. 以为 ?: 与 JS 的 || 一样 → Kotlin 只针对 null（没有 undefined，"" 和 0 不会因为「假值」被替换）。

题目 9 · 错误处理：抛异常与捕获（对应概念 05） ​

难度：基础

题目：实现 divide(a: Int, b: Int): Int，除数为 0 时抛出自定义异常 DivideByZeroException("除数不能为零")；调用方用 try/catch/finally 捕获并打印错误信息，异常时返回 0。

要求：

  • 自定义异常类继承 Exception
  • 用 try 作表达式（val r = try { ... } catch { ... }）
  • finally 里打印「计算结束」，验证无论成功失败都会执行

提示：前端锚点——try/catch/finally 语法与 JS 完全一致；差异是 Kotlin 的 try 是表达式，可以直接赋值给变量。

参考答案
kotlin
// 自定义异常：继承 Exception，可带消息
class DivideByZeroException(message: String) : Exception(message)

fun divide(a: Int, b: Int): Int {
    if (b == 0) throw DivideByZeroException("除数不能为零")
    return a / b
}

// try 是表达式：两个分支返回同类型 Int
fun safeDivide(a: Int, b: Int): Int = try {
    divide(a, b)
} catch (e: DivideByZeroException) {
    println("捕获到业务异常：${e.message}")
    0
} catch (e: Exception) {
    println("捕获到其他异常：${e.message}")
    0
} finally {
    println("计算结束")   // 无论成功失败都会执行
}

fun main() {
    println(safeDivide(10, 2))   // 计算结束 → 5
    println(safeDivide(10, 0))   // 捕获到业务异常：除数不能为零 → 计算结束 → 0
}

要点解析：

  1. throw 是表达式，也可以写在 Elvis 右侧：val b = input ?: throw IllegalArgumentException()。
  2. try 作表达式时，try 块和所有 catch 块的最后一个表达式类型要兼容（这里都是 Int）。
  3. 多个 catch 从具体到宽泛排列，否则宽泛的 Exception 会先匹配，具体的分支永远进不去（编译器会警告）。

常见错误：

  1. 空 catch {} 静默吞掉异常 → 出错时毫无痕迹，排查问题时最痛苦。至少 println 或 Log.e。
  2. 把 finally 当「成功回调」用 → 它失败时也会执行，不能放「只有成功才做」的逻辑。
  3. 自定义异常忘了继承 Exception → 抛出的对象不是 Throwable，编译报错。

题目 10 · 综合：带超时重试的安全查询（对应概念 04 + 05） ​

难度：综合

题目：实现 suspend fun safeGetUser(id: Int): String，串联本级别的空安全、错误处理与异步三个知识点：

  1. ID 小于等于 0 → 直接抛 IllegalArgumentException("ID 必须为正数")
  2. 用 withTimeout(2000) 包住 fetchUser(id)，超时后重试，最多重试 3 次
  3. 3 次都失败 → 返回 "未找到用户（已重试 3 次）"，不崩溃、不静默
  4. 成功 → 返回 "找到：User1"

要求：

  • 每次失败都要打印原因（超时 / 其他异常），不能静默吞掉
  • 全程不使用 !!
  • 在 main 里验证三种输入：1（成功）、-1（抛参数异常，用 try/catch 兜住）

提示：前端锚点——这就是 Promise.race([fetch(), timeout(2000)]) + for 重试循环 + TS 严格空检查的组合。

参考答案
kotlin
import kotlinx.coroutines.*

data class User(val name: String, val age: Int)

// 模拟网络请求：1 秒返回；id 为 999 时模拟「慢到超时」
suspend fun fetchUser(id: Int): User {
    delay(if (id == 999) 3000 else 1000)
    return User("User$id", 20 + id)
}

// 带超时与重试的获取：成功返回 User，三次都失败返回 null（用可空类型表达「没有」）
suspend fun fetchWithRetry(id: Int, maxRetry: Int = 3): User? {
    repeat(maxRetry) { attempt ->
        try {
            return withTimeout(2000) { fetchUser(id) }   // 超时 2 秒
        } catch (e: TimeoutCancellationException) {
            println("第 ${attempt + 1} 次请求超时，准备重试")
        } catch (e: Exception) {
            println("第 ${attempt + 1} 次请求失败：${e.message}")
        }
    }
    return null   // 重试耗尽：返回 null 让调用方决定，而不是自己崩溃
}

suspend fun safeGetUser(id: Int): String {
    // 参数校验：require 不成立时抛 IllegalArgumentException
    require(id > 0) { "ID 必须为正数，收到 $id" }

    val user: User? = fetchWithRetry(id)
    // 安全调用 + Elvis：把「没有结果」翻译成友好文案
    return user?.let { "找到：${it.name}" } ?: "未找到用户（已重试 3 次）"
}

fun main() = runBlocking {
    println(safeGetUser(1))
    // 找到：User1

    println(safeGetUser(999))
    // 第 1 次请求超时，准备重试
    // 第 2 次请求超时，准备重试
    // 第 3 次请求超时，准备重试
    // 未找到用户（已重试 3 次）

    // 调用方对「参数错误」负责：用 try/catch 兜住，而不是让进程崩掉
    try {
        safeGetUser(-1)
    } catch (e: IllegalArgumentException) {
        println("参数错误：${e.message}")   // 参数错误：ID 必须为正数，收到 -1
    }
}

要点解析：

  1. 用类型表达结果：「可能没有」用 User?；「参数非法」用抛异常。两者分工明确——前者是正常业务分支，后者是调用方的错。
  2. require(condition) { message } 是参数校验的标准写法（还有 check 校验状态、error 直接抛），比手写 if (!ok) throw ... 简洁。
  3. 超时专用异常是 TimeoutCancellationException（继承自 CancellationException），它必须单独 catch 且不吞掉——协程取消靠异常传播，随便吃掉会让取消失效。

常见错误：

  1. catch (e: Exception) 一把兜住所有异常 → 会把 CancellationException 也吞掉，破坏协程的取消机制。先 catch 具体的超时异常，或 catch 后判断 e is CancellationException 再 rethrow。
  2. 重试失败时返回一个「假 User」（如 User("", 0)）→ 调用方无法区分「查无此人」和「请求失败」，用 null 或 Result 才对。
  3. 在 repeat 里写 return@withTimeout 之类的错误标签 → 标签写错会导致重试逻辑直接失效（要 return@repeat 或像上面那样直接 return 出函数）。
