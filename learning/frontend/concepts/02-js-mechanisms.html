02 · JS 语言机制深入 ​

概念简介 ​

会写 JS 和懂 JS 是两回事。多数工程师每天在用闭包、箭头函数、class——但闭包为什么能造成内存泄漏、class 的本质是什么、this 为什么"忽隐忽现"、提升和暂时性死区到底怎么回事——这些机制层面的东西,平时用不到,出问题时却找不到根因。

本篇把 JS 的五个核心机制一次理清:闭包与内存、原型链与 class 本质、this 四种绑定、作用域链与提升、执行上下文与调用栈。重点不是复述语法,而是每个机制背后的内存模型和运行模型,以及生产中的真实代价:一个泄漏、一个多态调用、一个错误绑定,都可能让线上页面出问题。

核心内容 ​

1. 闭包与内存模型 ​

闭包 = 函数 + 它引用的外层作用域链。闭包让函数记住出生环境,代价是:只要闭包活着,它捕获的整个作用域对象就活着,即使外层函数早已返回。

js
// 反模式:闭包持有大对象,长期存活 → 泄漏
function createHandler(id) {
  const hugeData = new Array(1000000).fill(id); // 百万级数据
  return function () { console.log(id); };      // 闭包只用了 id,却拽着整个作用域
}
const handlers = [];
for (let i = 0; i < 100; i++) {
  handlers.push(createHandler(i)); // handlers 常驻 → 1 亿个元素无法回收
}
// 修复:只捕获需要的东西,大对象移到闭包外或按需传入
function createHandlerFixed(id) {
  return () => console.log(id); // 不引用 hugeData,作用域里就没它
}

要点:闭包捕获的是整个作用域对象(可变环境),不是单个变量。let 循环每次迭代创建独立作用域,而 var 只一个——这正是经典循环闭包问题(var i 打印 5)的根源。

2. 原型链与 class 的本质 ​

class 是语法糖:内部就是一个构造函数 + prototype 对象。new 干了四件事:创建空对象、把 [[Prototype]] 指向 Constructor.prototype、以该对象为 this 执行构造器、返回该对象(构造器显式返回对象则覆盖)。

js
class Animal {
  constructor(name) { this.name = name; }        // 实例自有属性
  speak() { return `${this.name} 叫了`; }        // 挂在 Animal.prototype 上,所有实例共享
}
// 等价于:
function AnimalEs5(name) { this.name = name; }
AnimalEs5.prototype.speak = function () { return `${this.name} 叫了`; };

// 生产启示:方法放原型上共享一份,实例属性放构造器里
// 反模式:在构造器里定义函数,每个实例复制一份,百万实例 = 百万份函数
class Bad {
  constructor() { this.speak = () => this.name; } // 闭包换性能,不必要
}

原型链查找:obj.speak 先查自身,再沿 [[Prototype]] 链逐级向上,直到 Object.prototype,再没有就是 undefined。这也是"给 Object.prototype 加属性会污染所有对象"的原因。

3. this 的四种绑定 ​

this 不是"指向定义它的对象",而是调用时由调用方式决定的动态绑定:

js
// 1. 默认绑定:非严格模式 → globalThis;严格模式 → undefined
function show() { console.log(this); }
show();

// 2. 隐式绑定:谁调用,this 是谁
const obj = { name: 'A', show() { return this.name; } };
obj.show(); // 'A'
const detached = obj.show;
detached(); // undefined/报错 —— 隐式绑定在拆解时丢失

// 3. 显式绑定:call/apply/bind 手动指定
const bound = obj.show.bind(obj); // bind 返回新函数,永久锁定 this

// 4. new 绑定:构造器内 this = 新建对象,优先级最高
// 箭头函数例外:this 取词法作用域(定义时的外层 this),没有自己的 this

生产坑:事件处理器里 onClick={this.handleClick} 隐式绑定丢失 → 组件必须用箭头函数属性或构造器里 bind。优先级:new > 显式 > 隐式 > 默认。

对象的 this 注意点:对象字面量方法里用箭头函数,this 取定义处的外层(模块/全局),不是对象本身——"对象方法 + 箭头函数"组合是 this 误判的高发区;解构 const { show } = obj 同样拆断隐式绑定。

4. 作用域链、提升与暂时性死区 ​

作用域链在定义时确定(词法作用域),沿链查找变量。提升:var 声明提升到作用域顶(值为 undefined),function 声明整体提升;let/const 声明提升但处于"暂时性死区"(TDZ),声明前访问直接 ReferenceError。

js
console.log(typeof beforeVar); // undefined —— var 提升,不报错
// console.log(beforeLet);      // ReferenceError —— TDZ,哪怕 typeof 也抛错
var beforeVar = 1;
let beforeLet = 2;

// 生产启示:先声明后使用是硬规矩;依赖提升的代码(函数声明后置)让调用栈更难读
// 块级作用域:{} 内 let/const 独立成域,for 的 let 每轮独立

5. 执行上下文与调用栈 ​

每次函数调用创建执行上下文(变量环境 + 词法环境 + this 绑定),压入调用栈;返回时弹出。栈深度溢出 → Maximum call stack size exceeded。深递归、JSON.stringify 循环引用、无限 render 都会爆栈。

js
// 演示调用栈与闭包引用关系
function outer() {
  let x = 1;
  function inner() {
    x++;                    // 沿作用域链找到 outer 的 x
    return x;               // inner 的 [[Environment]] 引用 outer 上下文
  }
  return inner;             // outer 返回后其上下文本应销毁,但因 inner 引用而存活
}
const count = outer();
count(); // 2 —— 这就是闭包的本质:被引用而存活的执行上下文

常见陷阱 ​

  • 闭包拖拽大对象:函数只用一个变量,闭包却整体捕获外层作用域,大数组/大字符串无法回收;把大对象定义在闭包之外或传入参数。
  • 循环 + 闭包:for (var i...) 里注册回调,i 全部指向最终值;用 let 或立即执行函数建立独立作用域。
  • 隐式绑定丢失:const fn = obj.method; fn() 或把方法作为回调传出去,this 变成 undefined(严格模式)或 window;用 bind 或箭头函数。
  • 构造器返回对象:new 时构造器若显式 return 一个对象,this 白建——返回对象会覆盖实例;返回原始值则被忽略(只有对象会覆盖)。
  • 依赖提升写代码:把函数调用写在函数声明之前,靠提升"恰好能跑",重构时提取到模块顶层顺序一变就炸;始终先声明后使用。
  • class vs 工厂函数选错:class 适合有原型共享方法的大量同类实例;若你需要真正的私有变量且实例少,工厂函数(闭包私有)更简单——两者不是哪个"更高级",是内存模型不同。

练习建议 ​

  1. 基础:写出四种 this 绑定的最小示例,并解释箭头函数为什么能"穿透"隐式绑定;用严格模式对比行为差异。
  2. 进阶:用 ES5 语法实现一个 class 等价物(含 extends 的原型链继承),跑通实例化、方法共享、super 调用,验证对 class 本质的理解。
  3. 综合:审查你手上线上项目的一个模块:找出 1 处闭包潜在泄漏(事件监听/定时器)、1 处隐式绑定丢失风险、1 处提升依赖,用本篇机制解释根因并修复。

对照其他技能 ​

  • Android/Kotlin:闭包对应 lambda 捕获的 this@Outer 引用(Kotlin 编译器为每个捕获变量生成 Cell 类);this 的隐式绑定对应成员引用 obj::method 的接收者绑定。
  • iOS/Swift:闭包捕获列表 [weak self] 就是显式管理闭包强引用——和 JS 闭包泄漏是同一个问题,Swift 用所有权语法强制你面对它。
  • 鸿蒙/ArkTS:箭头函数语义与 TS 一致(词法 this),@Observed/@State 的引用追踪对应 JS 闭包引用链的观察者版本。
  • Python:def 函数与嵌套作用域(LEGB)几乎等同 JS 词法作用域,但闭包修外层变量要 nonlocal 声明,JS 直接闭包+重新赋值即可。
  • Java:内部类捕获外部变量必须是 final(等价于 JS 闭包捕获的"每循环独立"语义),JS 的 let 即编译期自动完成这件事。
