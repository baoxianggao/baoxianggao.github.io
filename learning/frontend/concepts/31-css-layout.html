31 · CSS 布局 ​

前置：30 CSS 核心概念 · 预计：2~2.5 小时

概念简介 ​

如果说选择器与盒模型决定了「元素长什么样」，布局决定的就是「元素放在哪」。过去十年 CSS 布局经历了三次范式更替：表格布局 → 浮动 + 定位 → Flexbox + Grid。今天还在用浮动做整体布局的代码，基本都是历史包袱。

本篇聚焦五件事：常规流与脱离流的三种方式、Flexbox 的一维布局、Grid 的二维布局、响应式与容器查询、以及一批已经可以放心用的现代特性。核心主张：布局选型只有一条判据——你要控制的是一个方向还是两个方向：一维用 Flexbox，二维用 Grid，其余都是特例。

核心内容 ​

1. 常规流：一切布局的起点 ​

常规流（normal flow）是浏览器默认的排布方式：块级元素垂直堆叠、行内元素水平排列。所有脱离流的手段（浮动、定位、flex、grid）都是在它的基础上做「逃逸」。

css
.block  { display: block; }         /* 独占一行，width/height 生效 */
.inline { display: inline; }        /* 与文字同排，width/height 无效，垂直 padding 不撑开行高 */
.inline-block {                     /* 折中：同排显示，但可设宽高 */
  display: inline-block;
  width: 120px;
  vertical-align: top;              /* inline-block 默认基线对齐，常需要调这个 */
}
.none { display: none; }            /* 完全移出渲染树，不占位（visibility: hidden 仍占位） */

要点：display: inline-block 的元素之间会有一个空白间隙（HTML 里的换行被渲染成空格）。消除办法：父元素 font-size: 0 后子元素再设回来，或者干脆改用 Flexbox——这也是它逐渐被淘汰的原因之一。

浮动（float） 现在只剩一个正当用途：文字环绕图片。整体布局请用 Flexbox/Grid。

css
.article img {
  float: left;              /* 图片浮动，文字环绕 */
  margin: 0 1rem 1rem 0;
}
.article::after {           /* 清除浮动：浮动元素脱离流，父容器高度会塌陷为 0 */
  content: '';
  display: block;
  clear: both;
}
/* 现代写法：父容器 display: flow-root 同样能包住浮动子元素，且不需要伪元素 */
.article { display: flow-root; }

2. 定位：relative / absolute / fixed / sticky ​

position 让元素脱离或偏移常规流，四者行为差异如下：

值是否脱离流偏移基准是否占位典型用途
static否–是默认值，top/left 无效
relative否自身原位置是微调位置、作为 absolute 的包含块
absolute是最近的已定位祖先否徽标、下拉菜单、遮罩层内元素
fixed是视口否固定头部、悬浮按钮（祖先有 transform 时退化为 absolute）
sticky否（相对流内）最近的滚动祖先是吸顶导航、表头、列表分组标题
html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<title>定位行为对比 Demo</title>
<style>
  body { margin: 0; font: 14px/1.6 system-ui; }
  .panel {
    position: relative;         /* 关键：absolute 子元素的定位基准 */
    height: 120px;
    margin: 16px;
    background: #eef2ff;
  }
  .badge {
    position: absolute;         /* 相对 .panel 定位，因为 .panel 是已定位祖先 */
    top: 8px; right: 8px;
    background: #dc2626; color: #fff;
    padding: 2px 8px; border-radius: 999px;
  }
  .nudge {
    position: relative;         /* 相对自身原位置偏移，原位置仍占位 */
    top: 10px; left: 20px;
    background: #fef3c7;
  }
  .sticky-header {
    position: sticky; top: 0;   /* 必须有 top/left 等阈值，否则等同 relative */
    z-index: 10;                /* 吸顶时需要 z-index 才不被后续内容盖住 */
    background: #4f46e5; color: #fff;
    padding: 12px 16px;
  }
  .back-to-top {
    position: fixed; right: 24px; bottom: 24px;   /* 相对视口 */
    padding: 10px 16px; border-radius: 999px;
  }
</style>
</head>
<body>
  <div class="sticky-header">吸顶导航（sticky）</div>

  <div class="panel">
    相对定位的容器（relative），作为 absolute 的包含块
    <span class="badge">NEW</span>
  </div>

  <div class="panel">
    <span class="nudge">相对自身偏移 20/10，原位置仍占位</span>
  </div>

  <div style="height: 1200px; padding: 16px;">撑高页面，滚动观察吸顶与固定按钮</div>
  <button class="back-to-top">回到顶部</button>
</body>
</html>

要点：absolute 找不到已定位祖先时，会一路回溯到初始包含块（视口大小的矩形），这是「元素莫名其妙跑到页面左上角」的根因。同时记住 sticky 的两个失效场景：祖先元素有 overflow: hidden/auto（滚动容器变成了那个祖先），或父容器高度不够（没有可粘滞的空间）。

3. Flexbox：一维布局 ​

Flexbox 解决「沿一个方向分配空间」。记牢两根轴：主轴由 flex-direction 决定，交叉轴垂直于它。

css
.row {
  display: flex;
  flex-direction: row;          /* 主轴水平（默认），column 则垂直 */
  justify-content: space-between; /* 主轴对齐 */
  align-items: center;            /* 交叉轴对齐 */
  gap: 12px;                      /* 子项间距，不需要再用 margin 负值的老套路 */
  flex-wrap: wrap;                /* 允许换行，否则子项会被压缩 */
}
/* 多行时，align-content 控制「行与行」在交叉轴上的分布 */
.row--wrap { flex-wrap: wrap; align-content: flex-start; }

flex 是 flex-grow / flex-shrink / flex-basis 的简写，四个常用预设要背下来：

css
.item       { flex: initial; }  /* 0 1 auto：不放大、可缩小、基准为自身尺寸（默认） */
.item       { flex: 1; }        /* 1 1 0%  ：等分剩余空间，basis 归零所以真正等分 */
.item       { flex: auto; }     /* 1 1 auto：按内容比例放大（不是等分） */
.item--fix  { flex: none; }     /* 0 0 auto：固定尺寸，绝不伸缩 */
/* 三列布局：两侧固定，中间自适应 */
.layout { display: flex; }
.layout aside { flex: 0 0 200px; }
.layout main  { flex: 1; min-width: 0; }  /* min-width: 0 是关键，见常见陷阱 */
html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<title>Flexbox 常见套路 Demo</title>
<style>
  body { margin: 0; font: 14px/1.6 system-ui; }
  .app { display: flex; flex-direction: column; min-height: 100dvh; }

  .header { display: flex; justify-content: space-between; align-items: center;
            padding: 12px 16px; background: #4f46e5; color: #fff; }
  .nav { display: flex; gap: 16px; }

  .main { flex: 1; display: flex; gap: 16px; padding: 16px; }
  .side { flex: 0 0 180px; background: #eef2ff; padding: 12px; }
  .content { flex: 1; min-width: 0; background: #f9fafb; padding: 12px; }

  /* 卡片列表：自动换行 + 等宽拉伸 */
  .cards { display: flex; flex-wrap: wrap; gap: 12px; }
  .card { flex: 1 1 200px; background: #fff; border: 1px solid #e5e7eb; padding: 12px; }

  /* 底栏固定在视口底部：靠 main 的 flex:1 撑开，而不是 position: fixed */
  .footer { padding: 16px; background: #111827; color: #fff; }

  /* 「最后一个推到右边」：margin-inline-start: auto 吃掉剩余空间 */
  .toolbar { display: flex; gap: 8px; align-items: center; margin-top: 16px; }
  .toolbar .spacer-end { margin-inline-start: auto; }
</style>
</head>
<body>
  <div class="app">
    <header class="header">
      <strong>Logo</strong>
      <nav class="nav"><a href="#">首页</a><a href="#">文档</a><a href="#">关于</a></nav>
    </header>

    <div class="main">
      <aside class="side">侧边栏 180px 固定</aside>
      <main class="content">
        <div class="cards">
          <div class="card">卡片 A</div>
          <div class="card">卡片 B</div>
          <div class="card">卡片 C</div>
          <div class="card">卡片 D（缩窄窗口观察换行）</div>
        </div>
        <div class="toolbar">
          <button>保存草稿</button>
          <button class="spacer-end">取消</button>
          <button>发布</button>
        </div>
      </main>
    </div>

    <footer class="footer">底栏：内容不足一屏时也贴在底部</footer>
  </div>
</body>
</html>

要点：flex: 1（basis=0）与 flex: auto（basis=auto）区别很大——前者等分容器宽度，后者按内容比例分配剩余空间。做等分列用 flex: 1，做「主内容区占满剩余」用 flex: 1 也行，但侧栏一定要 flex: none 或 flex: 0 0 <宽度>，否则会被压缩。

4. Grid：二维布局 ​

Grid 解决「同时控制行和列」。当你的布局需要行与列都对齐（后台框架、仪表盘、卡片网格、表单）时，就该用 Grid 而不是套三层 Flexbox。

css
.grid {
  display: grid;
  /* fr = 剩余空间份额；repeat 简化重复值 */
  grid-template-columns: 200px 1fr 1fr;      /* 固定 + 两列等分 */
  grid-template-columns: repeat(3, 1fr);     /* 三等分 */
  /* 响应式网格：自动填充列数，每列最小 240px，最大 1fr */
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 16px;                                  /* 行间距与列间距 */
  /* auto-fill vs auto-fit：容器宽但子项少时，fill 保留空轨道，fit 把空轨道塌缩让子项撑满 */
}

网格线是 1 起始的编号（也可用负数从末尾数），跨轨道用 span：

css
.grid { display: grid; grid-template-columns: repeat(12, 1fr); gap: 16px; }
.hero   { grid-column: 1 / -1; }        /* 从第 1 根线到最后一根 = 占满整行 */
.side   { grid-column: span 3; }        /* 跨 3 列 */
.body   { grid-column: 4 / span 6; }    /* 从第 4 根线起跨 6 列 */

用 grid-template-areas 描述整体骨架，可读性远超数字：

html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<title>Grid 后台布局 Demo</title>
<style>
  * { box-sizing: border-box; }
  body { margin: 0; font: 14px/1.6 system-ui; }

  .shell {
    display: grid;
    min-height: 100dvh;
    grid-template-columns: 200px 1fr;
    grid-template-rows: 56px 1fr 48px;
    grid-template-areas:
      "header header"
      "side   main"
      "footer footer";
    gap: 1px;
    background: #e5e7eb;      /* gap 露出的底色即分隔线 */
  }
  .shell > header { grid-area: header; background: #4f46e5; color: #fff; padding: 0 16px; display: flex; align-items: center; }
  .shell > aside  { grid-area: side;   background: #fff; padding: 16px; }
  .shell > main   { grid-area: main;   background: #fff; padding: 16px; }
  .shell > footer { grid-area: footer; background: #fff; padding: 0 16px; display: flex; align-items: center; }

  /* 窄屏：重排区域，不需要改 HTML，也不需要动子元素的 grid-column */
  @media (max-width: 768px) {
    .shell {
      grid-template-columns: 1fr;
      grid-template-rows: 56px auto 1fr 48px;
      grid-template-areas:
        "header"
        "side"
        "main"
        "footer";
    }
  }
</style>
</head>
<body>
  <div class="shell">
    <header>管理后台</header>
    <aside>导航菜单</aside>
    <main>内容区（缩放窗口到 768px 以下观察重排）</main>
    <footer>© 2026</footer>
  </div>
</body>
</html>

要点：minmax(min, max) 里的 min-content/max-content/auto 很有用——grid-template-columns: minmax(0, 1fr) 能防止长内容撑破轨道（等价于 flex 里的 min-width: 0）。另外 place-items: center（align-items + justify-items 的简写）是 Grid 里做居中最省事的方式。

5. 响应式：媒体查询与容器查询 ​

布局要适配的是可用空间，而可用空间未必等于屏幕宽度——一个卡片组件可能出现在 320px 的手机里，也可能出现在 1200px 页面的 300px 侧栏里。容器查询解决的正是这件事。

html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">  <!-- 必须，否则移动端按 980px 虚拟视口渲染 -->
<title>媒体查询与容器查询 Demo</title>
<style>
  * { box-sizing: border-box; }
  body { margin: 0; font: 14px/1.6 system-ui; padding: 16px; }

  /* 移动优先：基础样式是窄屏，用 min-width 逐级增强 */
  .list { display: grid; gap: 12px; grid-template-columns: 1fr; }
  @media (min-width: 640px)  { .list { grid-template-columns: repeat(2, 1fr); } }
  @media (min-width: 1024px) { .list { grid-template-columns: repeat(3, 1fr); } }

  /* 用户偏好查询：尊重系统设置，无障碍的低成本收益 */
  @media (prefers-color-scheme: dark) { body { background: #111827; color: #e5e7eb; } }
  @media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
  @media (hover: hover) { .btn:hover { background: #4338ca; } }  /* 触屏不粘滞 hover 态 */

  /* 容器查询：组件的样式跟随「父容器宽度」，而不是屏幕宽度 */
  .card-wrap { container-type: inline-size; container-name: card; }  /* 声明为查询容器 */
  .card { display: grid; gap: 8px; padding: 12px; background: #f3f4f6; }
  @container card (min-width: 400px) {
    .card { grid-template-columns: 120px 1fr; align-items: center; }  /* 容器够宽才变横向 */
  }
</style>
</head>
<body>
  <div style="display: grid; grid-template-columns: 2fr 1fr; gap: 16px;">
    <div class="card-wrap"><div class="card">宽容器里的卡片 → 横向排布</div></div>
    <div class="card-wrap"><div class="card">窄容器里的卡片 → 纵向排布</div></div>
  </div>
</body>
</html>

要点：容器查询必须先给容器设 container-type: inline-size（注意：这会让它成为尺寸 containment 容器，其高度不再由内容撑开，需要显式高度或在另一个维度用别的布局）。媒体查询管「页面级断点」，容器查询管「组件级自适应」，两者互补。

常用断点参考：640px（大手机/小平板）、768px（平板竖屏）、1024px（平板横屏/小笔电）、1280px（桌面）。不要为了对齐设计稿去发明一堆断点，通常 3-4 个够用。

6. 现代特性速览 ​

这一批特性近两年已全浏览器可用，可以放心写进生产代码：

css
/* :has() —— 「父选择器」，根据后代/后续兄弟的状态反向设置样式 */
.card:has(img) { grid-template-columns: 120px 1fr; }   /* 有图才变横向排版 */
.field:has(input:invalid) label { color: #dc2626; }      /* 输入非法时高亮 label */
.card:not(:has(.badge)) { padding-block: 8px; }          /* 无徽标时收紧内边距 */

/* 逻辑属性 —— 用「书写方向」而非物理方位描述，天然支持 RTL 与竖排 */
.card {
  margin-inline: auto;            /* 水平居中：等价于 margin-left/right: auto */
  padding-block: 16px;            /* 上下内边距 */
  padding-inline: 24px;           /* 左右内边距 */
  border-inline-start: 3px solid var(--brand);  /* 起始边（LTR 是左，RTL 是右） */
  inset-inline-start: 0;          /* 定位偏移的逻辑写法，替代 left */
}

/* aspect-ratio —— 预留比例空间，消除图片/视频加载导致的 CLS */
.thumb { aspect-ratio: 16 / 9; width: 100%; object-fit: cover; }
.avatar { aspect-ratio: 1; width: 40px; border-radius: 50%; }

/* gap —— Flexbox 与 Grid 都支持，多列布局（columns）也能用 */
.toolbar { display: flex; gap: 8px 12px; }   /* row-gap column-gap */

/* clamp() —— 流体排版，一行搞定「最小值 / 理想值 / 最大值」 */
h1 { font-size: clamp(1.5rem, 4vw, 3rem); }   /* 视口越宽越大，但不超过 3rem */
.container { width: min(1200px, 100% - 2rem); margin-inline: auto; }  /* 不超过 1200px，两侧留白 */

/* 文本排版细节 */
h1, h2 { text-wrap: balance; }    /* 标题多行时各行星度均衡，避免最后一行孤字 */
p { text-wrap: pretty; }          /* 避免段落末行只剩一个词 */

/* 滚动与层级 */
.scroller { scrollbar-gutter: stable; }       /* 预留滚动条位置，避免出现滚动条时跳动 */
.modal { position: fixed; inset: 0; }         /* inset: 0 = top/right/bottom/left 全 0 */

要点：逻辑属性（margin-inline / padding-block / inset-inline-start）在做国际化（RTL）时省掉整份 RTL 覆盖样式表，新项目建议默认使用。:has() 虽然强大，但要注意它不计自身优先级，括号内最具体的选择器才计入（见 30 篇）。

常见陷阱 ​

  • flex 子项 min-width: auto 导致溢出：Flex 子项默认最小尺寸是内容尺寸，一段长 URL 或 white-space: nowrap 的文本会把容器撑破，flex: 1 也不起作用。解法：min-width: 0（Grid 里对应 minmax(0, 1fr)）。这是 Flexbox 最高频的坑，没有之一。
  • absolute 找不到定位父级：想让徽标贴在卡片右上角，结果跑到页面角落——因为祖先里没有 position: relative/absolute/fixed/sticky。给目标父容器加 position: relative 即可。
  • fixed 被祖先的 transform/filter/will-change 破坏：这些属性会创建新的包含块，让 fixed 元素相对该祖先而非视口定位。弹层挂在有 transform 的容器里就会错位，解法是把弹层 Portal 到 body 下。
  • sticky 不生效：三个常见原因——没写 top/left 阈值；祖先链上有 overflow: hidden/auto/scroll（滚动容器被换成了那个祖先）；父容器高度等于元素高度，没有可粘滞的行程。
  • height: 100% 无效：百分比高度依赖父元素有确定高度。父元素高度是 auto 时，height: 100% 计算为 auto。解法：父级链上给确定高度，或用 min-height: 100dvh + flex 撑开。
  • Grid 轨道被内容撑破：grid-template-columns: 1fr 里的 1fr 最小值是 auto（即内容最小宽度），长单词会顶开轨道。用 minmax(0, 1fr) 明确把最小值设为 0。
  • gap 与 margin 混用导致间距翻倍：子项上还留着旧的 margin-right，叠加上父级 gap。迁移到 gap 时应清掉子项间距。
  • 媒体查询用 max-width 写桌面优先：改动时要同时维护两端断点，越改越乱。统一移动优先（基础样式 + min-width 增强）。
  • 容器查询忘了设 container-type：@container 不生效，且容器高度不再由内容撑开导致布局塌掉（inline-size 只约束行内方向，块方向需要自己保证高度）。
  • z-index 无效：只对已定位元素（非 static）生效；且受层叠上下文限制——父元素创建了层叠上下文（opacity < 1、transform、isolation: isolate 等）时，子元素的 z-index 再大也出不了父元素。

练习建议 ​

  1. 基础：纯 CSS 实现「圣杯布局」（顶栏 + 左侧栏 + 主内容 + 底栏，底栏在内容不足一屏时仍贴底），分别用 Flexbox 和 Grid 各写一遍，对比代码量与可读性。
  2. 进阶：做一个自适应卡片网格——repeat(auto-fill, minmax(240px, 1fr)) 打底，再用容器查询让卡片在「容器宽度 ≥ 400px」时切换为图文横排。在 320px 手机、768px 平板、1440px 桌面三种视口下验证。
  3. 综合：实现一套后台管理框架布局：Grid 定义整体骨架（header/side/main/footer）、grid-template-areas 做窄屏重排、侧栏可折叠（切换 grid-template-columns 的值并加过渡）、主内容区滚动而侧栏固定，吸顶表头用 position: sticky。
  4. 拓展：用 :has() 重构一个表单——校验失败时高亮 label 并显示错误提示、勾选「其他」时才展开输入框，全程不写一行 JS。

用 /practice frontend CSS 布局 生成更多针对性练习。

对照其他技能 ​

  • Android / Compose：Row / Column 对应 display: flex 的 flex-direction，Modifier.weight(1f) 对应 flex: 1，Arrangement.SpaceBetween 对应 justify-content: space-between，Modifier.fillMaxSize() 对应 width: 100%; height: 100%。差异在于 Compose 没有 min-width: auto 的溢出坑，也没有脱离流定位——需要叠加时用 Box（对应 position: relative + absolute 的组合）。
  • iOS / SwiftUI：HStack / VStack 对应 Flexbox 的一维模型，Spacer() 对应 margin-inline-start: auto 或 flex: 1，LazyVGrid 对应 CSS Grid 的 repeat(auto-fill, minmax(...))，ZStack 对应绝对定位叠加。SwiftUI 的 frame(maxWidth: .infinity) 与 CSS 的 flex: 1 是同一套「占满剩余空间」心智。
  • 鸿蒙 / ArkUI：Row() / Column() 直接对应 Flexbox，Flex({ wrap: FlexWrap.Wrap }) 对应 flex-wrap，layoutWeight(1) 对应 flex: 1，Grid() / GridItem() 对应 CSS Grid，Stack() 对应定位叠加。ArkUI 把这些能力封装成声明式组件，心智负担比 CSS 的选择器 + 层叠低不少。
  • Python / Java：Tkinter 的 grid(row=, column=)、JavaFX 的 GridPane + ColumnConstraints（setHgrow / 百分比宽度）与 CSS Grid 的网格线、fr 单位几乎是同一套模型；Swing 的 BorderLayout（NORTH/SOUTH/CENTER）则等价于本篇的 Grid 骨架 grid-template-areas。差别是它们需要手动把组件 add 进布局，而 CSS 是结构与样式分离。
  • Node.js：无布局概念，但要注意 SSR 场景——服务端渲染首屏时 CSS 若未加载完，布局会先塌陷再跳变（CLS）。用 aspect-ratio 与显式尺寸预留空间是跨端通用的解法。
